## 工具与验收变化

新增`npm run prepare:scripts`，一批共用一次角色库和生产验收上下文。逐项检查原文字节、路径边界、角色数、稳定ID、团队与夜表，失败项单列；重复或已注册目标拒绝覆盖。普通模板补缺复用已确认人数事实，继续调用现有人数计算、生产配座、确认和夜序代码，不另建技能判定引擎。

同一人数能力的旧板规则ID先归为一个规则，避免引入多个“必须同时选择”的人数修正。补模板时不把旧板的整句上下文说明当作新组合事实，保留具体来源与选项。特殊开局仍需专门模板。输出永远是未注册、未确认草稿，分组报告不能替代板子规则复核或实际技能测试。输入、输出、错误码和发布步骤见[批量接入说明](LINK_BATCH_IMPORT_GUIDE.md)。

批量检查另外复现并修复了共用夜序问题：落难少女的爪牙通知原来以顺序0进入排序，会提前到队首；现在保留它在本板夜表的位置。回归先复现0与声明顺序不符，再验证接收者和信息保护保持、卡扎力当晚替换等既有流程通过。

## 同条件提速实测

计时范围只含Node工具冷启动、角色库加载、草稿准备、自动检查和输出。用相同九板、相同输入与相同代码，分别启动九次单项清单和一次整批清单；两轮交换先后顺序。每轮198个实际候选、396次首夜／后夜队列检查，45个输出文件逐字节一致。

| 轮次 | 逐个执行 | 一次批量 | 加速比 |
| --- | ---: | ---: | ---: |
| 逐个后批量 | 22.409秒 | 2.466秒 | 9.09倍 |
| 批量后逐个 | 20.483秒 | 2.547秒 | 8.04倍 |

两轮合计耗时比约8.56倍。259条引用按完整定义、原能力文本和团队归为149个复核组；这表示可减少重复复核，不是149个技能都已经实际发动。来源、作者规则、相克与板子组合仍分别检查。人工复核、浏览器、真实AI、构建和部署不在以上计时范围，不能据此声称整批上线快了8倍。
