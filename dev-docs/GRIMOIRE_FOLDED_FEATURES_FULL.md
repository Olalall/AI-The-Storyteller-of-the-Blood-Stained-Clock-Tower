## 1. 夜序与夜间逐项记录

**纯记录模式（现状）**

NightWorkbench 独立全屏页：96–160px 页头 + 250px NightPlayerCarousel 转盘 + CurrentWakeCard 两栏（左事实/右记录，内含 6 列 seat-grid 目标网格）+ 被强制 position:static 的 NightActionBar + 页尾 NightCloseFooter。

**魔典模式**

环变成夜序的空间光标：当前项座位是全屏唯一暖金焦点环，后续两项打 ①② 冷灰角标，已确认项打 ✓，已暂缓项打「缓」。250px 转盘降级进 core —— 双 RoleDisc small(58px)「当前 / 下一位」+ 两侧带座位号标签的 ‹ › 按钮，空间定位交给环，转盘不再占一屏。CurrentWakeCard 拆两半：能力说明与「今天发生了什么」事实条留在抽屉 half 档顶部（两行以内），目标选择直接点环上座位、抽屉里只留一行「已选：5号 ✕」回显 + 一个折叠的 SeatButton 号码网格作键盘/屏读/上半弧不可达时的 fallback；角色 chip 与结果按钮仍在抽屉，底栏仍是「确认后：停留 ⇄ 下一位」+ 唯一主动作「确认本项」。夜序清单（本局/官方两段、首夜/其他夜）走 core 底行「夜序 3/12」pill → 抽屉 full 渲染现有 NightQueueSheet。「结束本夜」移出页面，挂轨道右端「收尾」。

**为什么**

夜间最贵的一次认知动作是「下一个叫谁、他坐哪」，转盘只能回答前半句，环能同时回答两句且不占垂直空间；把 250px 转盘换成环上的一枚焦点环，直接把主任务提到首屏。目标选择从抽象号码网格变成指着真人的座位，与说书人在实体桌上「玩家指目标、我同步指回去确认」的手势一一对应。

**冲突风险与规避**

点环即改目标，容易被读成「工具在替我选/在自动结算」。规避：环上点击只写 draft.targets，草稿目标用虚线暖金描边 + 「目标」小字，与已落账的实线标记视觉分明；死亡座位照样可点（很多能力能选死人），只标注不 disable；夜序光标不因生死/毒醉自动跳过。落账入口仍只有抽屉底栏一处，missingReason 判定链按目标→角色→结果的规范顺序修好后再上环，避免环上选了目标而结果区提示还停在「选结果」。

## 2. 白天提名 / 举手 / 暂列 / 处决

**纯记录模式（现状）**

DayWorkbench 两栏并排（步骤1 提名卡 | 步骤2 举手卡），门槛 number input，死亡座位举手后长出 26px 的「标死亡票」药丸，暂列结果单独一卡，处决确认条追加在页面最底部常在视口外。

**魔典模式**

提名：环上提名人 token 出现暖金实心起点三角、被提名人出现终点三角，两者之间画一条 1px 冷青弧（唯一一处连线，只表达「这一次提名」）；选人 = 点环，落到抽屉分段当前指向的槽。举手：进入计票子态后每个 token 变成打卡键，点一下出现 ✋ + 「举」+ 计数序号；死亡座位举手后在其卫星位长出一枚 44px 的「死亡票」二次确认 chip（取代 26px 药丸，且不再把整行推下去）。core 实时显示 举手N / 门槛M / 差X，三档色 + 三档文字。可选「顺时针唱票指针」：从被提名者起的一枚高亮点，说书人每点一次前进一位，纯视觉节拍器。暂列 / 处决 / 无处决走抽屉的单列步骤序列（讨论→提名→举手→暂列→处决），一次只展开一步，其余折成 44px 摘要条；处决落账后该座位在环上加帷幕 + 「本日处决」角标。

**为什么**

提名投票是白天唯一有强时序的环节，而环恰好是这个时序的物理形状（说书人站中央顺时针转一圈）。把举手打卡放到环上，说书人的视线路径和身体动作一致——眼睛顺时针扫、手指顺时针点——比在一张 6 列网格里找座位号快且不易跳行。

**冲突风险与规避**

环上直接点举手 + core 显示门槛，很像一台自动计票裁定器。规避：门槛只算不裁（纯算术不是规则裁定），达标不自动处决、不自动改生死；「记录本轮票型」和「记录处决」仍是说书人手点的唯一写入口，处决按钮是 danger 且带二次确认与「本次处决造成死亡」独立勾选（弄臣/魔鬼代言人）；二次提名、死人提名只给 warning 不阻断（Banshee 这类反例存在）；唱票指针永远不自己前进。另需保留 raisedSeatIds 的逐人留痕，不能因为环上好点就退化成只记总数——那是本产品的证据链本体。

## 3. 玩家状态编辑（生死 / 中毒 / 醉酒 / 标记）

**纯记录模式（现状）**

入口在 Dashboard 的 PlayerStatusBoard 卡片，点座位卡 → PlayerStatusSheet 全屏页 → 改 life/poisoned/drunk → 选记入哪个段 → 「确认状态」按钮追加 player_state_changed（带 expectedBefore 乐观锁）。夜间工作台内改不了，必须离开。

**魔典模式**

长按座位（或 idle 单击）→ SeatActionBar 锚定浮层，3×2 网格：存活/死亡、中毒、醉酒、加标记、更换角色、座位卡。点其中任一格只写本地 draft，环上立刻以虚线幽灵 chip / 幽灵帷幕呈现；抽屉同时从 peek 升到一条「确认 5号 状态」的单动作条（死亡时为 danger 色），点了才 dispatch。「记入哪个段」的下拉保留在这条确认条上，默认取当前相位。完整 PlayerStatusSheet（含相关记录）仍可从座位卡进抽屉 full。PlayerStatusBoard 卡片在魔典模式下消失——环本身就是那张卡片的空间版，档案页保留一份列表版供逐行核对。

**为什么**

「夜里确认了一个死亡结果，然后要去别的页面把人改死」是当前最容易漏的一步，也是黎明差分播报会说谎的根因。把状态编辑贴到座位上，这一步的代价从「退出→找卡→改→回来→重新定位」降到「长按→点两下」，同时保住了两段式确认。

**冲突风险与规避**

一点就改会滑向自动结算，也会在暗光下误触改死人。规避：草稿—确认两段是硬性的，SeatActionBar 上的点击永不 dispatch；死亡格用 danger 色且与其他五格隔一行；沿用现有 expectedBefore 乐观锁，段落已关闭或状态被他处改过时确认条自行失效并给回执；不提供批量改多人；「AI 建议加中毒」与「说书人自己加中毒」在环上用同一种幽灵样式但带不同来源角标（✨ vs 无），确认后都写同一条记录。

## 4. 更换角色

**纯记录模式（现状）**

入口是 PlayerStatusBar 里的「更换角色」按钮 → RoleChangeSheet 全屏页：先选角色、再选原因、底部唯一主动作「确认改为X」，确认后 token 加 changed 角标、状态栏显示「本夜仍按X」。

**魔典模式**

SeatActionBar 的第五格「更换角色」→ 抽屉 full 原样渲染现有 RoleChangeSheet，一行代码级别的容器替换。确认后环上该 token 直接换成新角色的官方 WebP 并挂 RoleDisc 已有的 changed 角标（右下角冷青 RefreshCw），token 下沿名字牌显示「已变更 · 原X」，夜间当前项仍在抽屉里标「本夜仍按X」。L1 遮蔽态下 token 仍是「隐」，changed 角标照常显示——「这个座位换过角色」本身不是秘密身份。

**为什么**

换角是本产品少数已经做对的流程（先选后因、唯一主动作、后果说明不滚出屏幕），没有任何理由重做；它需要的只是一个更近的入口和一个能立刻看到结果的地方。环给了后者：换完抬眼就能确认自己没点错座位。

**冲突风险与规避**

在「魔典」上换角色，最容易被理解成「改了身份就生效了」。规避：确认区固定文案「仅记录 · 不发送 · 夜序不自动调整」原样保留；夜序队列里的 roleName 不变、技能说明继续标注原队列角色；未完成草稿存在时该格 disabled 并提示走「清空重选」，避免一次误点把换角入口永久锁死。

## 5. 本局记录与更正

**纯记录模式（现状）**

四个别名散在三处：Dashboard「最近记录/日记」、GameEndSheet 底部「本局记录」、复盘页「当局日志」；白天工作台根本没有入口。TimelineHistorySheet 点条目直奔可写更正表单。

**魔典模式**

入口唯一且恒定：轨道右端「本局记录 N」，六个相位与档案页全程可见。魔典模式额外给它一个空间索引能力：打开后抽屉 full 渲染 TimelineHistorySheet，列表滚动时当前聚焦条目涉及的座位在环上亮冷青描边（谁提名了谁、谁死了、谁被改了角色）；反向路径是点环上座位 → 座位卡「相关记录」区（projectSeatActivity 已有投影）。更正仍是「先详情后更正」，更正态在画布顶部挂常驻冷青条。

**为什么**

被玩家当众质疑「你昨晚是不是记错了」时，说书人需要的不只是找到那条记录，还要在 3 秒内说出「是 7 号」。文字列表回答前者，环回答后者；两边互相高亮，等于把一条记录的「谁」和「什么」同时摆在眼前。

**冲突风险与规避**

看历史条目时环显示的是当前状态，容易被当成「那一刻的局面快照」，在正被质疑的场合尤其危险。规避：一进回看/回放，画布加 data-mode="replay" 降饱和 + 顶部明写「环显示的是当前状态，不是当时快照」；坚决不用 timeline 反推历史局面（数据不足的字段会被投影函数猜出来，再以权威只读态呈现，这是评审明确否决的）。高频的夜间内联「追加更正」保留原路径不加层。

## 6. AI 配板

**纯记录模式（现状）**

Dashboard 的「AI配板」按钮 → SetupPanel 全屏页：SetupCandidateBrowser 候选 → 采用为草稿 → setup-seat-grid 文字按钮（tap-tap 交换 + HTML5 drag）→ 伪装三张 select → 人数修正条 → 合法性检查 → 底部「确认配板」。

**魔典模式**

开局态画布进入配板环：token 显示分配到的角色但默认 L1 遮蔽（配板时玩家常常已经落座），抽屉 full 渲染现有 SetupPanel。采用 AI 候选后不直接落账，而是在环上整圈以幽灵态预览（虚线描边 + 角色图标 40% 不透明 + 顶部「AI 候选 · 待确认」条），点抽屉底栏「确认配板」才实体化。座位交换 = 点两座，环上给一段 200ms 的交换弧线动画作为回执；更换角色走 SeatSeatEditor。人数修正条、合法性检查、伪装三张一律留在抽屉，不上环——它们是清单不是局面。

**为什么**

配板的本质就是「一圈人分别是谁」，而这正是环的原生表达。更重要的是它给了 AI 建议一个可整体扫视的呈现面：一屏看完 12 个角色的分布，比读一张文字网格更容易发现「三个信息角色挤在一侧」这类结构问题。

**冲突风险与规避**

在环上摆角色，是全案离「可编辑数字魔典」最近的一步。规避：环上只允许两种离散动作——交换、更换，没有自由布局、没有形状选择、没有任何位移自由度，座位角度永远由人数唯一决定；HTML5 drag 只在 (pointer: fine) 保留，触屏关闭；配板环只在开局态存在，一旦确认就并入常规环，不留「编辑模式」开关。另需给 SetupCandidateBrowser 补一个返回出口（当前唯一出口「采用为草稿」会重建 draft、作废全部手动交换且无撤销）。

## 7. AI 夜间结算建议

**纯记录模式（现状）**

CurrentWakeCard 结果区的「AI推荐」按钮 → 选中同一枚结果按钮并标「AI建议」，下方 SettlementAssistPanel 展开「建议结果 / 建议记录 / 告知玩家 / 状态确认 / 风险提醒」五张小卡（卡中有卡，已超两层）。

**魔典模式**

魔典上的形态就是「待确认草稿幽灵」，且不新增任何卡片：AI 建议给 3 号加中毒 → 3 号 token 卫星位长出一枚虚线描边、40% 不透明的「毒」chip，右上一枚 ✨ 微角标，chip 下方一行 --type-meta 的「待确认」。点它 = 就地落账（并让抽屉底栏主动作闪回一次，明示这一下等于按了底栏）；长按它 = 否决并留一行原因。建议改结果时仍按设计系统「结果只出现一份」：直接选中抽屉里那一枚 outcome 按钮并标「AI建议」，SettlementAssistPanel 瘦身为一行依据 + 「展开依据」，五张小卡收进折叠。人工改选后显示「已改为说书人选择」。

**为什么**

AI 的输出终于有了一个和它的性质匹配的形状：它是一个「叠在局面之上、还没落地的东西」，虚线幽灵就是这句话的视觉直译。说书人扫一眼环，就能分清哪些是自己记下的事实、哪些是机器的提议，而不需要读文字去辨别。

**冲突风险与规避**

幽灵做得太像实体，就变成了「AI 已经替我改了状态」。规避：幽灵一律虚线 + 40% 不透明 + 「待确认」文字标签三重区分，且始终画在实体标记层之上；每座位幽灵上限 2 枚，超出折叠为「AI 2 条建议」；幽灵永不进 timeline、永不进 playerState、永不参与黎明差分；遮蔽 L0 时幽灵连同其依据文本一起不进 DOM（AI 的推理草稿是全屏最敏感的东西之一）。语气沿用「我注意到了什么 + 请你复核」，从不阻断。

## 8. AI 复盘

**纯记录模式（现状）**

Dashboard「历史复盘」（挂着「危险动作」徽标，与「结束对局」同一张卡）→ GameEndSheet 的 review 段 → GameReviewPanel + GameAIReviewPanel：当局评价、关键转折、逐玩家评分草稿与锐评、优先回看。

**魔典模式**

只在局终出现，且与「结束对局」彻底拆开（不再共用一张卡、不再挂危险徽标）。轨道右端「收尾」→ 局终交接卡 →「本局复盘」→ 抽屉 full 渲染现有复盘面板。此时画布切到只读定格环：显示终局生死与角色（需要一次显式「揭示终局」点击才升 L2），点某个座位 = 抽屉滚到该玩家的评分草稿与关键行为，反向点评分卡片 = 环上该座位高亮。评分数字、锐评文本只在抽屉里，环上只做索引。

**为什么**

复盘时说书人和玩家往往围着同一块屏幕说话，「谁是谁、谁在第几夜死的」是全场提问频率最高的问题，一个定格的环能一次性回答，比逐条读日志快得多。而把评分留在抽屉里，是为了不让一个 AI 估算的数字获得「摆在局面正中央」的权威感。

**冲突风险与规避**

环 + 评分数字容易被读成官方结论；终局揭示可能在现场还没散时泄露。规避：「非客观评分」「草稿」「只按日志活跃度估算」的字样保留在抽屉里紧贴数字；环上不显示任何分数；揭示终局按钮的确认文案明写「确认现场已散再揭示」，且揭示态同样有自动落回 L1 的计时。

## 9. 发身份 / 伪装

**纯记录模式（现状）**

Dashboard「发身份」按钮 → IdentityDealSheet 全屏页：屏幕领取 / 实体抽牌两段，座位网格（屏幕模式下每格直接印着角色名）+ 右侧当前领取卡 + 单人 spotlight（默认遮住，两级揭示）。伪装三张在 SetupPanel 的 demonBluffs 里。

**魔典模式**

发身份是开局一次性叠加模式而非环的常态。进入后画布切 data-mode="deal"：强制降到 L1 并锁定（此时环上一个角色名都不出现），点一个座位 = 打开现有 spotlight（全屏、不透明、只有这一位、仍需两级揭示）；返回后该座位在环上打 ✓「已领取」角标，core 显示 8/12 领取进度，实体抽牌模式同理只记进度。伪装三张不上环（它们是不在场角色，环上没有它们的座位），落在 core 底行「本局备忘」pill → 抽屉里显示 bluff 组（组名 + 三个角色 + 展示给了谁 + 第几夜），首夜「恶魔信息」系统步骤卡直接读写这一组。

**为什么**

发身份是全流程里唯一一次必须把说书人的屏幕转向单个玩家的动作，环在这一刻的价值不是显示信息而是显示进度：谁领了、还差谁，抬眼一圈就清楚，不用在名单里数。伪装三张则是几轮之后自己一定会忘、而 AI 又极需要的上下文，给它一个固定的常驻落点。

**冲突风险与规避**

这是全案泄密风险最高的一处：若进入发身份时环恰好处于 L2，转屏给一号玩家看的那一秒会把全场都露出去。规避：进入 deal 模式强制 L1 且锁死揭示键；spotlight 是全屏不透明层，其余座位不进 DOM；退出 spotlight 立即回遮蔽、不保留上一次揭示态；现有 IdentityDealSheet 屏幕模式的座位网格直接印角色名这一点必须一并改成默认遮蔽、点开才看单个。

## 10. 剧本切换

**纯记录模式（现状）**

Dashboard 的「切换板子」按钮（与配板、发身份、倒计时并列在同一排工具条）→ ScriptLibrarySheet 全屏页；实际只允许空局切换，非空局时按钮 disabled 并提示先保存重置。

**魔典模式**

降级为 core 顶行那条「乌鸦渡口 · 12人」标识的点击目标 → 本局信息浮层（剧本、人数、知识版本、切换板子、开场白）。空局时它是主入口且醒目；非空局时「切换板子」保持 disabled + 一行说明。绝不出现在环上，也绝不出现在拇指可达区。

**为什么**

这是一局一次甚至零次的动作，却在现状里占着首屏工具条的一格，还紧挨着高频的配板与发身份。把它挪到 core 顶行的信息标识后面，既符合它的频率，又给了它一个语义正确的位置——它是「这一局是什么」的一部分，不是一个工具。

**冲突风险与规避**

几乎没有功能冲突，唯一风险是误触导致换局丢记录。规避：沿用现有的空局才可切换的守卫，非空局 disabled 并说明路径；切换前二次确认；入口放在拇指弧之外的 core 顶行，物理上就不容易被握持时蹭到。

## 11. 倒计时

**纯记录模式（现状）**

两处：白天工作台内的 DayTimer 卡（私聊/公聊、时长设置、开始/暂停/重置，超时后有渲染空洞）与 Dashboard 上并列的第四个顶层视图 PublicChatTimerPage 全屏页。

**魔典模式**

删掉顶层 timer 视图。白天计时态下环导轨本身变成进度弧——沿椭圆周长填充，这是环最自然的一次复用（一条已经存在的圆形轨道天生就是进度条）；core 中央放 mm:ss 大字 + 阶段名 + 「可开始提名」状态；控制键（开始/暂停/重置/时长/投屏）在抽屉 peek 档的一条 88px 横条里，不占 half 空间。「投屏」= 全屏不透明遮蔽层，层内只有时间、阶段名和一枚「收起」，收起后精确回到原步骤原滚动位；同时补齐现有超时后的三选一空洞（重新开始公聊 / 回到私聊 / 重置），与全屏层共用同一套按钮集。

**为什么**

把大字倒计时转给玩家看是每局必做的动作，现状的代价是整个白天工作台消失、票型草稿只靠暂存兜底。降级成遮蔽层后主视图一直在下面活着。而进度弧让说书人在不看数字的情况下用余光判断还剩多少——暗光下弧长比数字好读。

**冲突风险与规避**

进度弧若用暖金填充，会与「暖金 = 当前焦点」的纪律直接冲突，且一条全屏最亮的装饰性弧线正是焦点色纪律要清理的那类东西。规避：弧的填充用 --text-muted 冷灰，只有最后 60 秒的弧头点用暖金呼吸一次；投屏层必须真正不透明（不能半透明）、秘密内容不进 DOM、「收起」按钮与主确认不同色不同位，避免把平板拿回手里的那一刻误触确认。

## 12. 结束归档

**纯记录模式（现状）**

Dashboard 底部「结束对局」卡（与「历史复盘」共卡、共挂危险徽标）→ GameEndSheet 三步：声明胜方 → 保存本局（含导出）→ 勾选确认后重置。归档校验失败等回执只挂在第 2 步的 DOM 里。

**魔典模式**

入口收进轨道右端「收尾」→ 局终交接卡（页内覆盖，与黄昏/黎明/白天收尾同一族），交接卡里是唯一的 danger 按钮。抽屉 full 渲染现有 GameEndSheet 三步。画布在归档确认那一刻显示终局快照预览作为回执：谁死谁活、多少条记录，让说书人在按下不可逆按钮之前看到自己要归档的是哪个局面（阵营/角色仍需一次显式揭示）。归档完成后环清空为新局空态——一圈灰色座位占位 + 一枚「AI配板」主动作。全部回执（正在保存 / 已保存到本机 / 归档校验失败 / JSON已导出）改由轨道下方的全局 HostNotice 单例承载，其中破坏性失败常驻不自动收回。

**为什么**

不可逆动作需要的不是更多文字警告，而是一次「你看到的就是你要归的档」的具象回执；环恰好能在一屏内给出这个回执。同时把它从首页那张与复盘共用的卡片里拆出来，误触路径固定为「点收尾 → 读交接卡 → 点红色按钮」，摩擦力与破坏性成正比。

**冲突风险与规避**

终局快照要显示阵营就得升 L2，而归档往往发生在玩家还围着桌子的时候；另外「显示终局」容易被误解为工具在判胜负。规避：快照默认仍 L1（只显示生死与记录数），揭示需一次点击且文案提示确认现场已散；胜方永远是三选一的手动声明，工具不提示「恶魔已死」之类的胜负判断；exportArchive 去掉无归档时隐式保存的分支，改为 disabled + 「请先保存本局」；resetAcknowledged 与 winner 加入 open effect 的重置列表，避免关页面再打开把两步确认退化成一次点击。

## 13. 黄昏 / 黎明交接（新增，但必须与环共存）

**纯记录模式（现状）**

完全缺失。夜结束是「检查并关闭」→ onExit 回 Dashboard →「进入白天」三段跳；黄昏准备与黎明播报全靠说书人记忆。

**魔典模式**

两张交接卡都在抽屉 full 档，同时环进入对应的辅助态。黄昏：环上把「上一夜标注为持续到黄昏的效果」对应的卫星 chip 变成待到期的虚化态（只提示、不到期、不清除），core 显示上一天结论回执与本夜队列预览。黎明：环上用差分动画标出相对黄昏发生变化的座位——死亡座位帷幕落下、复活座位帷幕升起，core 用大字列出座位号；抽屉里是「只报生死，不报原因」的护栏条与「本夜 N 项记录标注了死亡结果，但玩家状态未更新 [去更新]」的核对提醒。主动作分别是「所有玩家闭眼 · 开始第N夜」「已宣布睁眼 · 进入第N天」。

**为什么**

黄昏与黎明是百科里明确存在、工具里完全缺失的两步，也是「白天→夜」「夜→白天」这两次跳转唯一自然的落点。黎明的差分尤其适合环：说书人要当众念出「本夜死亡的是 7 号」，而环能让这句话在念之前就被自己的眼睛校验一遍。

**冲突风险与规避**

差分动画极易被误读成「工具算出了谁该死」。规避：差分的两端都只取说书人已手改的玩家状态（黄昏快照 vs 当前 projectCurrentPlayerStates），绝不由夜间技能结果反推死亡；核对提醒条的措辞必须是提示而非断言；黄昏清单的勾选项一律不写 session、不改队列、不生成记录，离开即丢弃，文案统一用「请核对」而非「已处理」。

## 14. 遮蔽 / 防窥（贯穿全局的结构件）

**纯记录模式（现状）**

单一布尔 privacyShielded：开启后 CurrentWakeCard 整张卡被 230px 的 privacy-curtain 取代，Sheet 内秘密内容不进 DOM；「展示信息」会自动置位。没有中间档，也没有全局一键。

**魔典模式**

升为三级并成为魔典模式的默认设计前提。L0 全遮蔽：不透明幕盖住整块画布与抽屉，秘密内容不进 DOM，恢复需单指点大按钮。L1 席位视图（默认）：token 用 RoleDisc 现有的 concealed「隐」态，只显示座位号、昵称、生死、毒醉、具名标记、领取/夜序角标——这些都是玩家看到也无所谓、而说书人最常需要的量。L2 魔典视图：显角色图标与名称，需长按遮蔽键 600ms 或点+确认两段进入，90 秒无操作自动落回 L1，画布顶部常驻冷青条「魔典已揭示 · 剩余 62s」。另有 L1.5 单座位揭示：座位卡里只露这一位。触发路径：轨道右端 44px 遮蔽键（可见入口）+ 画布任意处双指点（盲操作路径）；进入发身份、投屏、展示信息时强制降级并锁定。

**为什么**

一块摊开的电子魔典是全屏最危险的东西——它把「谁是谁」这个整局唯一的秘密画成了一张一眼可读的图。所以魔典模式的默认态不能是魔典，必须是席位；角色是需要付出一次明确动作才换来的、且会自己过期的临时视图。这也让「说书人有时没有实体魔典」这个前提成立：他真正需要屏幕代替实体魔典的时刻是有限的几次，而不是全程。

**冲突风险与规避**

默认藏起角色，看起来像是把「魔典主视图」这个决策自我否定了。规避：提供一个本机设置「默认揭示（适用于有屏幕挡板 / 独立说书人席位的场合）」，默认关闭，且开启后自动过期机制仍然生效；同时保证 L1 下环仍承载夜序光标、举手、标记、生死、领取进度这些高频信息——即使一整局不升 L2，环也仍然是有用的主视图。另需确保 L0/L1 下 AI 的推理草稿、说书人给过的假信息记录、下一步计划一律不进 DOM，而不只是视觉遮住。
