# 批量接板：按完整流程提高吞吐量

目标是单位时间内完成验收并发布更多板子。第五批工具约8.56倍的计时只覆盖自动准备，九板整批从记录到巡检约两小时；这个数字不能证明端到端接板效率提高。

## 本轮调整

- 全库只整理一次，自动生成原文文件、来源、角色来源引用与夜序候选。已有共享角色板子不再按十板分批，也不逐板手写清单。
- 验收以稳定角色ID、来源版本、完整共享定义指纹和原文事实为单位。相同事实复用已确认映射；角色变了、原文变了或来源歧义未解决时失效或保持待核。原文别名和同名候选不自动变成已确认角色。
- 作者特殊规则、原文提示、首夜和后夜、人数修正、伪装与特殊组合仍逐板核对。每板的配板和队列检查由生产代码批量执行；未知角色、来源问题和特殊开局分别列待办，不阻断其余草稿生成。
- 完整回归、构建、隐私检查和部署按通过的一批执行一次。浏览器与真实AI围绕新增／变化机制及代表组合安排，保留板子关联和未覆盖项；不逐板重复测试同一份未变化的角色逻辑，也不将抽测当作全部组合或完整对局通过。

命令与输入边界见[批量导入说明](LINK_BATCH_IMPORT_GUIDE.md)。默认清单目标100是容量上限，不能把数量不足或规则待核的板子凑成已通过。

## 上轮工具建设探针

使用2026-10-21已锁定的同一份Clocktower Wiki快照：1267条记录、1189个来源家族，1047条带可解析完整JSON，220条缺原始JSON。按角色资料和来源校验生成27个普通板子的待核清单，无手写这27项角色引用。

随后直接调用批量准备工具：24个草稿生成，其中16个通过自动结构检查，走完352套实际配板和704个首夜／后夜队列；8个草稿缺足够模板，3个输入因原文角色类型与共享定义冲突被拒绝。三处错误按项隔离，完整报告保留。生成的草稿、身份候选、译文／版本差异及作者规则均未自动确认，来源依赖随`intakeReview`保留。

这里的“通过”只代表自动来源、结构、模板与队列检查，仍需核对角色身份、技能原文和板子组合。此次没有新增注册板包或部署，正式板包数量保持157；没有执行Ego或真实AI，也没有测得下一批完整上线耗时。角色来源分组包含原文版本、别名及作者附注，不可将分组数等同于独立角色数或未实现技能数。

相关18项回归、类型、lint和架构检查通过。回归覆盖不同来源ID的相同事实复用、同名异能不得确认、来源身份冲突、坏输入隔离、原文字节保留、不覆盖已有目录、复核依赖不能关闭，以及原文或共享定义变化使旧映射失效。

## 后续验收指标

下一批同时记录开始处理、发布和巡检完成时间，按“实际上线板数／总耗时”衡量，包括人工规则复核、失败处理、浏览器、真实AI和发布等待。分别记录首次建设流程与稳定重复批次；当前不承诺每小时能上多少板，也不将本轮自动探针耗时当作完整提速结果。

数据与私有配置保持；工具只在新目录输出资料，不修改已注册板子、现有对局、凭据或私人部署配置。
