# 问答界面精简与公开信息复查

问答侧窗改为常见聊天布局：上方一行显示当前板子和角色，点“更换”才展开搜索和选择；完成后收起。中间留给对话，底部保留输入和发送。开场仅留一句引导，使用说明收起，回答先显示结论和还缺的事实，依据、注意事项、引用与资料版本按需展开。切换问答范围不切本局，关闭不丢本页对话，失败保留问题；沿用原有只读权限和隐私遮蔽。

首次验证仅显示邀请口令表单，验证后再显示聊天输入，避免两个输入区并列。访问口令是站点邀请口令，由站主从私有配置获取，和 API 密钥不同。设备验证时长和已有授权保持。未改变对局结构、存储和服务器密钥。

复查时发现状态、配置检查和连通测试的返回仍包含真实模型标识，现统一显示“服务器私有模型”。旧页面仍能依非空字段识别配置就绪，服务器内部请求继续使用真实私有模型；模型配置本身不变。

公开发布只使用通用示例，不写私人 API 地址、密钥、模型标识、访问口令、个人部署信息和本机路径。提交作者使用公开的 noreply 地址；合并时也须明确指定该地址。发布前完成源代码与安装包扫描，确认通过后才可推送。

本轮重新下载全部公开发布附件并扫描嵌套文件，同时检查全部公开分支、标签的可达历史与提交信息。七条合并提交的作者邮箱已清理，第一步保留全部文件树。再将曾用模型标识纳入检查，发现三个历史文件的四十个旧对象仍有残留；第二步仅替换这些标识，保留全部提交数量和其他内容。GitHub 控制的旧 PR 引用、不可达对象和下载缓存仍需平台处理，已补充既有支持工单；不能将当前分支清理完成等同于平台缓存已清除。第三方已下载副本不在本仓库控制范围内。

使用负担：选板和说明不再一直挤占聊天；主动作只有发送，关闭和更换均有独立入口；输入、发送与资料展开支持触控及键盘。条件缺失继续直接显示，避免只看到结论便误当作完整裁定。
