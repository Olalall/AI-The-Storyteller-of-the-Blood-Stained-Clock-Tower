# 产品定位

## 一句话

以官方/实体魔典为主要空间视角，为线下说书人提供配板草稿、昼夜记录、夜序轮换、白天投票和 AI 建议草稿；说书人始终是唯一的权威操作者。

## 产品不是

- 不是第二套官方魔典，不复制官方面板的完整空间局面。
- 不是自动规则引擎：不自动结算技能、死亡、处决、胜负或昼夜切换。
- 不是线上游戏平台；常驻玩家端、玩家收件箱、官方魔典同步、半自动点击器、OCR 和真实 AI 接口均不属于当前原型交付。
- 魔典模式不构成玩家端。它画在说书人自己的设备上，没有第二个对端。「投屏 / 给单个玩家看」的全屏覆盖层是同一台设备上的临时显示，不涉及任何网络传输——这个区分是明确的，不是玩家端的先例。

## 主持工作流

1. **常驻面板是默认入口。** 它汇总剧本、当前配板、玩家状态、当前开放的昼夜记录段、最近记录和进入白天/夜晚的入口；点座位才显示身份、状态编辑与单座位结构化记录；暂列处决只在白天工作台显示。
   - **纯记录模式**（默认）下这条不变：屏幕一次只暴露一个座位的身份。
   - **魔典模式**下屏幕上另有一张座位环，供桌上没有实体魔典时使用。它是一块显示面而不是推演机——不判定、不结算、不推进相位。选择哪种模式记在 `hostingMode` 里，但那只是出处元数据，**禁止任何 reducer 读取**（由架构守门强制）。两种模式走同一条数据路径。
   - 魔典模式默认遮蔽，且遮蔽是「不进 DOM」而不是 CSS 覆盖。理由与全部边界见 `dev-docs/GRIMOIRE_MODE_BOUNDARY.md`。
2. **AI 配板。** 只有“剧本内容 + 同版本已核对规则知识包”完整时，才按人数、座位和玩家经验生成 3 套可解释候选；说书人可换角色、换座位、锁定或微调后再确认。AI 只提供草稿，不发送身份、不直接写入权威对局状态。
3. **夜晚工作台。** 说书人按首夜或其他夜的在场角色顺序逐位唤醒、记录选择与告知；夜序是独立展开的工作台，不常驻占用首页。已生成的告知内容可本地全屏展示给单个玩家；展示不会发送、已读、确认记录或推进夜序。
4. **白天工作台。** 说书人记录白天技能、提名、被提名人和票型；每轮计票只更新暂列结果，日终由说书人明确确认处决或无处决。白天节奏使用“私聊 → 公聊”两个可暂停、可恢复的本地计时；12 人默认 15 分钟 → 10 分钟，可分别设为 1–180 分钟，是主持预设而非官方规则，两个计时都不会结束今天或写入日志。
5. **统一对局记录。** 上述权威保存都追加到同一条时间线，常驻面板只读汇总，不另存一份摘要日志。
6. **AI API 设置。** 常驻页右上角齿轮配置接入地址、模型名字、超时和上下文等参数；API KEY 只允许作为本次测试输入，不进入前端源码、localStorage 或导出日志。

## 昼夜记录段合同（计划实现）

- 白天和夜晚是同级、独立的工作台；进入、浏览、预览、查询 AI 都不创建记录段，也不自动切换阶段。
- 每种类型最多保留一个开放记录段；一个开放的白天段与一个开放的夜晚段可以同时存在，便于说书人按现场情况自由补记。
- 某类首次权威保存创建对应昼夜记录段；同类开放段存在时继续写入该段。显式“结束本夜/结束今天”后，下一次该类权威保存才创建下一编号。编号不倒退：已有第3夜时，首次白天记录为第3天。
- 更正和补记必须回到原 `segmentId`，不能因为修改旧记录而新建昼夜或改变编号。
- 时间线按记录段和时间显示为“第1夜 / 第1天 / 第2夜 / 第2天”等清晰标签；编号只用于避免倒退，不自动跳转、关闭或协调阶段。

## 配板原则（计划实现）

- 默认一次给出 3 套候选，例如耐玩均衡、全员参与、戏剧反转；名称是侧重点，不代表固定角色模板。
- 合法性、玩家经验适配、双方发挥空间和预计节奏优先于差异度。差异度只是轻量约束：同一批候选尽量有可感知差别，但不为了不同牺牲合理性。
- 配板合法性包含基础人数、角色明确声明的开局人数修正、已核对冲突和恶魔伪装范围；“需要说书人选择”的修正必须明确选择，系统只报告人数缺口，不自动替换角色。
- 剧本 JSON 只能提供角色与顺序，不能单独获得“智能配板”资格。导入后必须同版本生成并核对规则知识包；缺少关键 coverage 时保留为导入草稿，不进入可开局剧本列表。来源或社区版本仍需 spot-check、但关键 coverage 已完整的板子可以开局，AI 建议显示“需人工核对”，不冒充已核验。
- 不使用历史配板黑名单；相同组合可以再次出现。相同配板由不同玩家、座位和临场选择主持时，本来就会产生不同对局。
- 开局前可持续微调角色与座位。开局后仍允许调整，但只能经说书人确认后追加“配板差异/角色变更”事件，从确认时点向后生效；不得回写历史记录或当前夜序快照。

## 当前阶段

- 已有：常驻面板、AI 配板样例、统一对局会话、首页状态板、夜间唱片式聚焦与独立夜序、白天提名/投票、可恢复双阶段计时、单人信息展示、响应式与只读记录投影。
- 下一步：版本化剧本知识包、外来者修正/冲突检查、恶魔伪装建议、昵称显示、多夜回放、具名标记编辑、AI API 设置页与 7/12/15 人完整多日验收。
- 仍不做：登录、常驻玩家端、玩家收件箱、真实消息、自动结算、自动昼夜推进、官方魔典同步、半自动点击器、DOM 注入、WebSocket 同步或逆向接口。

## 视觉关系

- 夜间工作台借鉴播放器的“当前播放、上一首、下一首、播放列表、进度”认知。
- 不借鉴自动播放、循环、随机、滑过即完成。
- 完整夜序只通过按钮打开独立 Sheet；常驻面板保留入口与紧凑摘要。
- 白天与夜晚在信息层级上同等重要；两者通过同级入口进入各自专注工作台。

## 官方/实体魔典协作取舍

- MVP 只做手动录入与“配板交接卡”：把本工具确认的座位、昵称、身份和恶魔伪装输出为人工核对清单，由说书人照着录入官方/实体魔典。
- 官方/实体魔典中的后续变化也由说书人手动录入本工具；本工具不尝试保持两边自动一致。
- 不做官方魔典同步器、半自动点击脚本、DOM 注入、WebSocket 监听、逆向接口或坐标校准方案。
- 截图/OCR 从当前路线移出；未来即使重新评估，也只能是待确认草稿，不能自动写入本局或官方魔典。
