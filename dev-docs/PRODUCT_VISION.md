# 产品定位

## 一句话

为线下说书人提供配板草稿、昼夜记录、夜序轮换、白天投票和 AI 建议草稿。提供两种可切换的主视图模式：纯记录模式假设说书人另有实体魔典，工具只做记录台；魔典模式提供电子魔典作为主视图，由说书人直接操作局面。两种模式下说书人都是唯一的权威操作者，工具不做任何自动结算。

## 产品不是

- 不是自动规则引擎：不自动结算技能、死亡、处决、胜负或昼夜切换。魔典模式提供的电子魔典是说书人手动操作局面的界面，不是官方魔典的替代品、不与官方应用同步，也不复刻官方应用的视觉外观与商标标识；界面交互参考社区工具（如 botc.games）的信息组织方式，不进行像素级复制。
- 不是线上游戏平台；常驻玩家端、玩家收件箱、与官方应用的数据同步、半自动点击器和 OCR 均不在路线内。真实 AI 接入已通过后端 provider 实现，但仍只产出草稿。
- 魔典模式不构成玩家端。它画在说书人自己的设备上，没有第二个对端。「投屏 / 给单个玩家看」的全屏覆盖层是同一台设备上的临时显示，不涉及任何网络传输——这个区分是明确的，不是玩家端的先例。

## 主视图模式合同

这个工具原来只有一种主视图，文档里没有「模式」这个概念。加入电子魔典之后，最可能的两种走偏是：魔典变成第三套并列界面，夜序、投票、AI 建议在魔典之外又开一套；或者魔典做完之后纯记录模式无人维护，悄悄退化成不可用。下面六条是防这两件事的合同，不是风格偏好。

作者原话，评审时以它为取舍依据：

> 现有全部功能（夜序、夜间记录、白天提名投票、本局记录、AI 建议、配板、发身份、复盘）要以辅助按钮等形式自然融入与电子魔典的交互，而不是并列的另一套界面。

1. **两种模式。** 纯记录模式（阶段轨道 + 主持台 + 交接卡，假设说书人另有实体魔典）与魔典 + 记录模式（电子魔典为主视图）。默认模式在开局前选择，局中可随时切换。
2. **同源。** 两模式读写同一 GameSession、同一时间线、同一持久化 key。切换不产生任何记录，也不改变阶段。切换换的是视图，不是程序——这条一旦破了，归档回放的就不再是当时那局，复盘和争议回溯这两个核心卖点同时失效。展开理由见 `dev-docs/GRIMOIRE_MODE_BOUNDARY.md` 第二章。
3. **融入而非并列。** 魔典模式下，夜序、夜间记录、白天提名投票、本局记录、AI 建议、配板、发身份、复盘一律以魔典上的辅助入口（座位上下文操作、顶部轨道入口、覆盖层）出现，禁止在魔典之外再挂一套等价的全屏工作台。两套等价界面意味着两套局部状态、两处要修的 bug、两份要同步维护的验收，而且说书人在桌边永远不知道该点哪一个。
4. **纯记录模式是保底通道。** 魔典模式的任何功能都不得成为完成一局主持的必要条件；每次发布前必须有一条纯记录模式跑完整局的验收。手边有实体魔典的说书人是本工具最早也最稳定的用户，让这条路径退化成不可用，等于砍掉一半适用面，而且退化通常不是被决定的，是被无人验收拖出来的。
5. **阶段推进的唯一门在两模式下相同。** 黄昏 / 黎明 / 收尾交接卡。魔典视图上的任何操作都不推进阶段（判据见下一节）。
6. **魔典视图不是权威源之外的第二真值。** 它渲染的是 `projectCurrentPlayerStates` 等既有投影，不得持有独立的局面状态。它自己算出来的东西活不过一次重渲染，也不进时间线、不进归档；一旦它开始持有状态，屏幕上的局面和存档里的局面就会分叉，而分叉了没人会发现。

## 魔典视图上不会发生的三件事：胜负、昼夜、死亡

纯记录模式下工具根本不持有局面，这三条几乎是免费的。魔典模式把整局摊在一屏上，实现门槛从「做不到」降到「顺手就能做」，而且都会以体贴的小优化形式提交，评审时很难拒绝——除非有成文判据。对应的实现级越界特征列在 `dev-docs/ABILITY_SETTLEMENT_BOUNDARY.md`。

- **胜负不判。** 魔典视图可以显示客观计数（存活数、已死数、阵营已知数），但禁止显示任何形式的结论性判定：「邪恶获胜」「善良只剩 X 人，恶魔胜利条件已达成」「胜负条件已满足」都不行。判据——UI 文案中不出现胜、负、获胜、结束条件达成一类词，除非它出现在说书人已手动选定胜方之后的回执里。说书人裁定胜负要看的东西远不止台面计数：角色能力的例外、玩家的谎、临场判罚都在其中；工具替他宣布一次，就是替他做了一次它没有依据做的判断，而说书人一旦开始信这个横幅，他就不再自己算了。
- **昼夜不推。** 相位推进的唯一入口仍是交接卡（黄昏 / 黎明 / 收尾）；魔典视图上的任何座位操作、标记操作、夜序操作都不推进相位。夜序光标的前进仍需说书人显式选择「停留 / 下一位」。判据——魔典组件树中不出现 dispatch 相位类 action。魔典模式会让说书人长时间停在同一个界面上，「顺手加一个自动切夜」的需求会自然浮现；一旦相位能被座位操作带着走，说书人就失去了「这一夜我确认结束了」的那个动作，而黄昏黎明交接卡是全部不可逆动作的唯一落点。
- **死亡不代切。** 魔典上的「裹尸布 / 死亡态」切换是一次独立手势，不得由夜间结果、投票结果或标记自动触发。魔典可以提示「本夜 2 项记录标注死亡结果，状态未更新」，不能替说书人更新。夜间记录写下的是「谁被指向」，谁真的死了取决于保护、抗性、身份和说书人的裁量；工具替他翻这一下，翻错了会在几分钟后以「他怎么还能投票」的形式暴露，而那时已经无法回溯是谁做的决定。

## 主持工作流

1. **常驻面板是默认入口。** 它汇总剧本、当前配板、玩家状态、当前开放的昼夜记录段、最近记录和进入白天/夜晚的入口。纯记录模式下点座位才显示身份、状态编辑与单座位结构化记录，不替代说书人手边的实体魔典；魔典模式下座位与标记常驻可见，由说书人直接操作，但仍不与任何外部魔典同步。暂列处决在两种模式下都只在白天步骤中显示。
   - **纯记录模式**（默认）下屏幕一次只暴露一个座位的身份。
   - **魔典模式**下屏幕上另有一张座位环，供桌上没有实体魔典时使用。它是一块显示面而不是推演机——不判定、不结算、不推进相位。选择哪种模式记在 `hostingMode` 里，但那只是出处元数据，**禁止任何 reducer 读取**（由架构守门强制）。两种模式走同一条数据路径。
   - 魔典模式默认遮蔽，且遮蔽是「不进 DOM」而不是 CSS 覆盖。理由与全部边界见 `dev-docs/GRIMOIRE_MODE_BOUNDARY.md`。
2. **AI 配板。** 只有“剧本内容 + 同版本已核对规则知识包”完整时，才按人数、座位和玩家经验生成 3 套可解释候选；说书人可换角色、换座位、锁定或微调后再确认。AI 只提供草稿，不发送身份、不直接写入权威对局状态。
3. **夜晚工作台。** 说书人按首夜或其他夜的在场角色顺序逐位唤醒、记录选择与告知；夜序是独立展开的工作台，不常驻占用首页。已生成的告知内容可本地全屏展示给单个玩家；展示不会发送、已读、确认记录或推进夜序。
4. **白天工作台。** 说书人记录白天技能、提名、被提名人和票型；每轮计票只更新暂列结果，日终由说书人明确确认处决或无处决。白天节奏使用“私聊 → 公聊”两个可暂停、可恢复的本地计时；12 人默认 15 分钟 → 10 分钟，可分别设为 1–180 分钟，是主持预设而非官方规则，两个计时都不会结束今天或写入日志。
5. **统一对局记录。** 上述权威保存都追加到同一条时间线，常驻面板只读汇总，不另存一份摘要日志。
6. **AI API 设置。** 常驻页右上角齿轮配置接入地址、模型名字、超时和上下文等参数；API KEY 只允许作为本次测试输入，不进入前端源码、localStorage 或导出日志。

## 昼夜记录段合同（计划实现）

- 白天和夜晚是同级、独立的工作台；进入、浏览、预览、查询 AI 都不创建记录段，也不自动切换阶段。
- 每种类型最多保留一个开放记录段；一个开放的白天段与一个开放的夜晚段可以同时存在，便于说书人按现场情况自由补记。
- 某类首次权威保存创建对应昼夜记录段；同类开放段存在时继续写入该段。显式“结束本夜/结束今天”后，下一次该类权威保存才创建下一编号。编号不倒退：已有第3夜时，首次白天记录为第3天。
- 更正和补记必须回到原 `segmentId`，不能因为修改旧记录而新建昼夜或改变编号。
- 时间线按记录段和时间显示为“第1夜 / 第1天 / 第2夜 / 第2天”等清晰标签；编号只用于避免倒退，不自动跳转、关闭或协调阶段。

## 配板原则（计划实现）

- 默认一次给出 3 套候选，例如耐玩均衡、全员参与、戏剧反转；名称是侧重点，不代表固定角色模板。
- 合法性、玩家经验适配、双方发挥空间和预计节奏优先于差异度。差异度只是轻量约束：同一批候选尽量有可感知差别，但不为了不同牺牲合理性。
- 配板合法性包含基础人数、角色明确声明的开局人数修正、已核对冲突和恶魔伪装范围；“需要说书人选择”的修正必须明确选择，系统只报告人数缺口，不自动替换角色。
- 剧本 JSON 只能提供角色与顺序，不能单独获得“智能配板”资格。导入后必须同版本生成并核对规则知识包；缺少关键 coverage 时保留为导入草稿，不进入可开局剧本列表。来源或社区版本仍需 spot-check、但关键 coverage 已完整的板子可以开局，AI 建议显示“需人工核对”，不冒充已核验。
- 不使用历史配板黑名单；相同组合可以再次出现。相同配板由不同玩家、座位和临场选择主持时，本来就会产生不同对局。
- 开局前可持续微调角色与座位。开局后仍允许调整，但只能经说书人确认后追加“配板差异/角色变更”事件，从确认时点向后生效；不得回写历史记录或当前夜序快照。

## 当前阶段

- 已有：常驻面板、AI 配板样例、统一对局会话、首页状态板、夜间唱片式聚焦与独立夜序、白天提名/投票、可恢复双阶段计时、单人信息展示、响应式与只读记录投影。
- 下一步：版本化剧本知识包、外来者修正/冲突检查、恶魔伪装建议、昵称显示、多夜回放、具名标记编辑、AI API 设置页与 7/12/15 人完整多日验收。
- 仍不做：登录、常驻玩家端、玩家收件箱、真实消息、自动结算、自动昼夜推进、官方魔典同步、半自动点击器、DOM 注入、WebSocket 同步或逆向接口。

## 视觉关系

- 夜间工作台借鉴播放器的“当前播放、上一首、下一首、播放列表、进度”认知。
- 不借鉴自动播放、循环、随机、滑过即完成。
- 完整夜序只通过按钮打开独立 Sheet；常驻面板保留入口与紧凑摘要。
- 白天与夜晚在信息层级上同等重要；两者通过同级入口进入各自专注工作台。

## 官方/实体魔典协作取舍

- MVP 只做手动录入与“配板交接卡”：把本工具确认的座位、昵称、身份和恶魔伪装输出为人工核对清单，由说书人照着录入官方/实体魔典。
- 官方/实体魔典中的后续变化也由说书人手动录入本工具；本工具不尝试保持两边自动一致。
- 不做官方魔典同步器、半自动点击脚本、DOM 注入、WebSocket 监听、逆向接口或坐标校准方案。
- 截图/OCR 从当前路线移出；未来即使重新评估，也只能是待确认草稿，不能自动写入本局或官方魔典。
