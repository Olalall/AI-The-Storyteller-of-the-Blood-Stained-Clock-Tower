## 统一会话与日终原子性

- 夜间运行态、草稿、光标、已确认夜间记录和角色变更只能经 `GameSession v1` 写入；不存在可供新页面写入的 v5 夜间持久化分支。
- 只有 v5 旧数据存在时，应一次性迁入 v1；已有有效 v1 时不得被 v5 覆盖；无效 v5 不得删除。
- 夜间首次确认和后续补正应与对应 `NightRun` 同一次提交；补正原夜已关闭时仍保留原 `segmentId`，不得新建下一夜。
- 夜间换角记录必须保存 `originNightRunId`；新夜“本局记录”不得投影旧夜的角色变更。配板微调的来源为 `null`，不得伪装为夜间换角。
- 白天处决必须在同一 reducer 命令中追加 `execution` 与 `player_state_changed`；无处决不得改变任何玩家状态；两者都不自动关闭白天或进入夜晚。
- 已开局后，过期配板草稿不得确认；调整座位集合必须与本局 `session.seats` 完全一致。

## UI 场景

- 390px：窄屏可完成当前角色记录，无横向溢出。
- 480px：模拟约三分之一 Pad 分屏。
- 720px：增强分屏。
- 1280px：独立横屏工作台。
- 夜间顺序一次点击打开，默认本局；可切换官方只读顺序。
- “本局记录 N”一次点击打开，按阶段显示确认技能、更正和角色变化；开关、展开详情不写状态。
- “更换角色”必须明确选择新角色并点击“确认改为X”；取消、未选择、同角色或未完成草稿都不能误写角色变更。
- 换角确认区必须同屏显示“原角色 → 新角色”和“仅记录 · 不发送 · 夜序不自动调整”。误点形成的未完成草稿可通过“清空重选”恢复，随后重新开放换角。
- 角色变更后 Token 显示新角色和原角色标记，本夜 `queue` 快照保持原角色且不自动重排；记录数只增加一条。
- 切换官方、关闭和重开不改变本局光标、草稿或进度。
- “AI推荐”只选中带来源标记的草稿结果；说书人确认前不写确认记录、不推进夜序。
- 结果只出现一次；AI依据最多一行，玩家告知保持独立预览。
- 底部只有一个主动作“确认本项”；“停留 / 下一位”作为确认后的分段选择。
- 草稿未满足确认条件时不显示“停留 / 下一位”；满足后才展开，并在390/480宽度铺满底栏。
- “稍后处理”不确认且不推进；“暂不更正”恢复最近确认快照且不新增更正记录。
- 玩家状态栏位于记录操作之前；存活、死亡、中毒、醉酒和具名标记均有不同图标、文字与颜色。
- 状态展示不自动改变技能结果、夜序适用性或当前光标；遮蔽时不泄露玩家状态。
- 遮蔽时本局记录只渲染“记录已遮蔽”，身份、目标、结果、告知和AI内容不进入可访问DOM。
- 390/480/720分屏必须保留“遮蔽”入口；遮蔽后角色变更角标和“原角色”文案也不得保留。
- 预览态底栏显示具体座位“回到N号 / 处理N号”，高度不超过80px；不出现禁用的完成控件。
- 将预览角色切换为处理位置只移动夜序光标；暂缓状态必须通过“恢复处理”显式解除。
- 角色图标使用400×400官方WebP原件，浏览器计算样式不包含额外滤镜，Token与图片中心误差不超过1px。
- 浏览上一/下一位不推进真实光标。
- 保存失败不推进；保存成功后才能下一位。
- 最后一位结束只显示夜间检查，不进入白天。
- 低亮度、遮蔽和减少动画可用。
- 首页不显示“暂列处决”；它只在白天投票工作台的“本日票面”中出现。
- 白天页头按“私聊 → 公聊”顺序提供两个计时：12 人主持预设为 15 分钟 → 10 分钟，可在“时长”中分别设置为 1–180 分钟；各段可开始、暂停和重置。私聊结束后必须由说书人显式开始公聊，刷新后按真实时间恢复，归零不结束今天、不写日志。
- 首页只显示同一份“私聊 → 公聊”计时摘要，不放置另一套开始、暂停或重置按钮；开场白仅给说书人本机查看、编辑和大字展示，关闭后不留下对局记录。
- 首页状态板只展示说书人需要的`座位号、当前角色、昵称、生命/中毒/醉酒/标记摘要`，并在标题区显示总人数与存活/死亡；点卡后才在说书人全屏页查看完整身份和相关记录。确认状态新增追加式 `player_state_changed`，不自动创建昼夜段、处决、判胜或切换页面；夜间状态栏读取同一投影。
- 夜间“展示信息”全屏只渲染待告知内容；关闭后工作台保持遮蔽，且不发送、不确认、不追加记录、不推进夜序。
- “结束本夜”先确认，再关闭当前夜间段并返回首页；不会自动进入白天。再次从首页进入夜晚时才创建独立的新夜草稿，首次确认才建立下一夜段。
- 白天“记技能/事件”先写入可恢复的 `dayActionDraft`，只有确认后才通过 `day_action` 追加到白天段；技能保留发动者与目标，公开事件保留涉及座位，首页和单人记录只按这些结构字段筛选。
- 12 人领域回归覆盖多目标、毒醉、夜间更正、夜间关闭、白天技能/公开事件、四轮票型、平票、死亡票、最终处决和结束今天；7/15 人及第1夜到第6天完整实机仍未验收。

## 下一阶段验收合同（待实现，尚未作为通过结果）

### 常驻面板与记录段

- 默认进入常驻面板；“进入夜晚”和“进入白天”同级可见，进入任一工作台或返回首页均不自动建立、关闭或切换昼夜记录段。
- 若不存在夜晚记录段，首次确认夜间技能/信息时原子创建“第1夜”；同夜继续确认多个角色、信息或补记时都归入“第1夜”。
- 若不存在白天记录段，首次确认白天技能、公开事件、提名或票型时原子创建与当前进度一致的白天标签；例如当前为“第3夜”时创建“第3天”，同日后续动作都归入该段。
- 开放的昼夜段允许同时存在；两者各自只能有一个开放段，仍不强制界面或时间线自动交替，但新标签不得低于另一类的已有编号。
- 只有“结束本夜/结束今天”能关闭对应段。段关闭后，下一次同类确认才建立“第2夜/第2天”；关闭不会自动进入另一工作台。
- 打开、关闭、浏览、预览、请求 AI、调整草稿、刷新页面和切换宽度均不得创建新段或改变段编号。
- 更正和补记必须显示原“第N夜/第N天”，并追加到原 `segmentId`；不能把更正显示为新的昼夜。
- 常驻面板的最近记录、当前开放段和座位状态在确认后立即更新，但首页没有独立可写日记。

### AI 配板

- 输入剧本、人数、座位与玩家经验后，显示 3 套明确标记“原型建议”的候选；候选包含角色/座位、简短理由、风险与节奏取向。
- 同一批候选以合法性、经验适配、双方发挥空间和预计节奏优先；候选有轻量差异，但不因追求不同而输出明显不合理方案。
- 不因历史使用过而强制排除相同配板；重复组合在合理时允许再次出现。
- 选择候选只进入配板草稿；换角色、换座位和重新生成不直接发送身份、不创建夜序、不改变玩家状态。
- 开局前可以连续微调并重新确认。开局后微调必须显示前后差异与生效时点；确认后只影响后续投影，不回写历史日志或当前夜序快照。
- AI 生成、采用候选、确认配板和线下身份交接是不同动作；AI 未被说书人确认前不改变任何权威状态。

### 白天提名与投票

- 一天可完成至少 4 轮提名；每轮显示提名人、被提名人、门槛、逐座位举手、死亡票和 0 票，并保存为追加式记录。
- “完成本轮计票”只保存本轮并清空当前举手草稿；它不能杀人、不能结束今天、不能进入夜晚。
- 每轮结束后，暂列结果能正确显示领先、被更高票覆盖、平票、未达门槛或无候选。
- 最高票只代表暂列处决，不代表死亡。只有说书人点击并确认“处决 N 号”后，才新增该座位的死亡状态变化和日终日志。
- “确认无处决”同样追加日终日志，但不改变任何玩家生死；两种日终确认后均回到常驻面板，不自动进入夜晚。
- 死亡票的资格和次数由说书人记录/确认；前端不以角色 ID 或自动规则自行裁定。

## 3秒检查

当前夜间原型中，说书人应能在3秒内说出：第几夜、正在处理的座位、当前角色、队列位置、毒醉/待核对状态、下一步按钮。

统一对局合同实现后，常驻面板还应能在3秒内说出：当前开放的第几夜/第几天、最近一次确认记录，以及进入白天或夜晚的明确入口；暂列处决只在白天工作台检查。
