# UI 设计系统

## 方向

“低光 Token 轮换台”：深墨蓝背景、暖金当前焦点、冷青信息提示。角色使用简洁的圆形 Token 与官方角色图标，不模拟黑胶唱片纹理。强调现场可读性，不做游戏大厅、企业后台或霓虹科技屏。

## Token

- 间距：4 / 8 / 12 / 16 / 24 / 32 / 40。
- 触控：最小 44px，主按钮建议 52px。
- 字体：中文正文使用系统黑体；阶段和角色标题使用中文宋体/衬线字体。
- 字号层级只使用 `meta(12px)`、`label(13px)`、`body(15px)`、`section(20px)`、`page-title` 五档 Token；辅助文本不得再临时缩到 11px 以下。
- 圆角：8 / 14 / 22，禁止随机圆角。
- 动效：150–260ms；尊重 `prefers-reduced-motion`。

## 当前共享组件

- `Button`
- `StatusBadge`
- `SeatButton`
- `RoleDisc`
- `Sheet`
- `StickyActionBar`

### 座位号码卡

- `SeatButton` 是夜间目标、白天提名和举手共用的号码输入，不是角色 Token。
- 外形使用至少 48px 高的圆角矩形键，只显示号码；不再把数字和“号”拆成两行。
- 选中态必须同时显示勾选、描边和颜色，并保留 `aria-pressed`；不能只用暖金底色表达已选。
- `subdued` 仅表示低强调，不能替代真正的 `disabled`；业务层不得把它当规则限制。
- 角色 PNG 与圆形 Token 只保留给 `RoleDisc`，避免把座位操作误解为另一套魔典。

## 业务组件

- `NightPlayerCarousel`
- `NightQueueList`
- `CurrentWakeCard`
- `GameRecordList`
- `RoleChangeSheet`

业务组件只有在真实页面验证稳定后才提升到共享组件层。

### 角色 Token

- 使用居中的浅羊皮纸底色、单层细边框和轻阴影，不模拟奖章、黑胶或多层金属圈。
- 角色图片使用完整官方透明画布并几何居中；图片盒距Token边缘2px，补偿素材自带的大透明边距。
- 角色图片使用官方400×400 WebP原件；渲染尺寸使用整数像素，不叠加图标级滤镜，避免Android合成时软化细线。
- 当前角色只增加一层细金边和轻微光晕；“正在处理”文字仍是主要状态信号。
- 不按角色ID写位移。少数非对称素材如需光学校正，必须使用独立视觉元数据，不得污染业务规则。

### 玩家状态栏

- 状态栏横跨技能和记录区，窄屏时必须先于目标、结果和底部确认动作出现。
- 固定顺序为生死 → 中毒/醉酒 → 具名人工标记。
- 每种状态同时使用图标、文字和语义颜色：存活、死亡、中毒、醉酒、标记不能只靠颜色区分。
- “需要核对”属于流程状态，不放进玩家状态栏。
- 首页玩家状态卡按`号码 / 当前角色 / 昵称 / 状态图标`三层投影；人数、存活/死亡集中在状态板标题区。中毒、醉酒和自定义标记用图标显示，完整身份和可写状态仍只在说书人全屏页确认。中毒、醉酒或死亡不能自动改变适用性、技能结果或夜序光标。
- 平板/PC 的本局速览可以点击座位号码，打开同一张全屏玩家状态页；速览自身不得编辑状态，只有全屏页的“确认状态”才能追加记录。

### 预览操作

- 预览角色时，底栏显示具体座位，例如“回到10号 / 处理11号”，不再使用两个含义不明的“当前”。
- “处理11号”只移动夜序光标，不确认记录、不执行技能，也不隐式恢复已暂缓的角色。
- 已暂缓角色切换为处理位置后，仍需显式点击“恢复处理”。
- 预览动作只放在记录区后的操作栏，角色轮播区不重复放置相同按钮；它不能覆盖当前记录卡或裁切底部内容。

## 夜间记录

- 默认使用“目标 → 角色 → 结果”的点击路径，不让说书人重复抄写已选内容。
- 点击结果只生成草稿；“确认本项”仍是唯一确认入口。
- 目标或角色改变后，旧结果立即失效，必须重新选择结果。
- 主流程不显示解释段落；技能、状态、历史和已生成记录使用短标签。
- 文本补充属于后续兜底能力，不得重新成为默认流程。
- “结果”只出现一份。AI建议直接选中同一结果选项，并在选项上显示“AI建议”。
- AI只在结果下方保留一行依据；人工改选后显示“已改为说书人选择”，不再增加独立AI卡片。
- 玩家需要收到的内容使用独立“告知玩家”预览，不与内部结算结果混排。
- 底部先选择“确认后：停留 / 下一位”，再点击唯一主动作“确认本项”。
- 长记录卡不提供第二个“本项操作”跳转；确认区保持在记录卡之后，不确认记录、不写日志、不推进夜序。不能为方便触达而恢复覆盖内容的假吸底栏。
- 顶部“返回本局”不应直接丢下正在编辑的夜间草稿：有草稿时先用页内确认条说明“草稿已保留，返回后可继续”，确认返回仍不写记录。白天同样只对可恢复的投票草稿作此承诺。
- 目标、角色或结果尚未选齐时，只显示缺失项和完成按钮；记录可确认后才展开“停留 / 下一位”，避免底栏提前占用两行。
- 次要动作固定为“稍后处理”；更正态对应“暂不更正 / 确认更正”。
- 分段选项和操作按钮均不小于44px，选中态同时使用勾选、文字和颜色。

## 夜间顺序

- 主界面只保留一个“夜间顺序”入口。
- Sheet 内使用“本局 / 官方”两段切换，每次打开默认本局。
- 本局条目可预览且显示座位、状态；官方条目只读，不显示本局进度。

## 本局记录

- 页头常驻的是“本局记录 N”入口，不是挤压夜间主任务的固定侧栏。
- 打开后按“第N夜 / 第N天”分组，组内最新记录在前；技能结果、AI采用、更正、角色变化使用短徽标区分。
- 记录列表只读；展开详情、关闭 Sheet 不得写状态。
- 所有产品二级工作台均使用不透明全屏页：夜序、日记、单玩家状态、角色调整、配板、记录/事件和计时设置不再按宽屏切回右侧浮层；遮蔽时秘密内容不进入 DOM。
- `Sheet` 仅作为无障碍与焦点管理基础；`presentation="page"` 是产品界面的默认展示方式。`ui-lab` 可以保留浮层示例，但不能反向成为业务页面模式。

## 更换角色

- 入口是玩家状态栏中的明确按钮“更换角色”，不隐藏在 Token 点击或长按中。
- Sheet 先选角色、再选原因，底部只保留一个主动作“确认改为X”。
- 确认区固定显示“原角色 → 新角色”和“仅记录 · 不发送 · 夜序不自动调整”，不能让后果说明滚出屏幕后只剩确认按钮。
- 确认后 Token 显示新图标和变更标记，并在角色名下显示“已变更 · 原X”；状态栏同时显示“本夜仍按X”。
- 本夜技能说明继续标注原队列角色，不自动切换技能、不重排夜序、不发送玩家信息。
- 未完成草稿存在时禁用换角，并在记录标题旁提供“清空重选”；不能让一次误点永久锁死换角入口。
- 当前板子角色图标全部使用官方工具制作者 WebP；角色选择器不得出现破图或用汉字冒充已有官方图标。

## 禁止

- 紫蓝渐变 SaaS 模板感。
- 卡片套卡片超过两层。
- Token 持续旋转、黑胶纹理或整页横滑。
- 状态仅靠颜色、危险动作紧邻主按钮、隐藏式长按入口。
