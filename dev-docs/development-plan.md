## 阶段 2.5：统一对局合同（已接入样例流程）

**目标：** 先消除“夜晚一套记录、白天一套记录、首页又一套摘要”的风险，再增加白天页面。

- [x] 定义 `GameSession`、`PlayerSeat`、`PlayerState`、`PhaseSegment`、`TimelineEntry`、`SetupCandidate`、`SetupDraft`、`ConfirmedSetup`、`VoteRound` 与 `StandingExecution` 的唯一合同。
- [x] 夜间运行态、确认记录与角色变更经单一 `GameSession` 命令原子提交；旧 v5 夜间样例仅允许一次性迁入 v1，后续不再作为持久化来源。
- [x] 记录段按 `night | day` 区分；每类最多一个开放段，白天段和夜晚段可并存。编号不倒退：已有第3夜时，首次白天记录为第3天。
- [x] 进入、浏览、预览、查询 AI 不创建记录段；首次权威保存才创建或复用对应开放段。
- [x] 返回本局不关闭昼夜段；夜间有未完成草稿、白天有未记录票型或技能/公开事件草稿时，先显示可恢复提示，说书人再显式确认返回。
- [x] `结束本夜/结束今天` 只关闭对应记录段；夜晚结束后返回本局，重新进入夜晚才显式创建下一夜草稿。
- [x] 更正、补记按原 `segmentId` 追加，不改变原昼夜编号。
- [x] 常驻面板只消费统一时间线与状态投影，不保存第二份可写摘要。

**可观察结果：** 同一夜连续保存多个角色仍都归入同一夜；第1夜未结束时可以保存第1天记录；若从第3夜演示快照补记白天则建立第3天。两个段的内容仍独立、可追溯。

## 阶段 3：常驻面板与 AI 配板原型（样例已实现）

### 3A. 常驻面板

- [x] 默认首页在剧本名下展示当前已开放的昼夜记录段；人数、存活/死亡集中在玩家状态板，暂列处决只保留在白天工作台。
- [x] 将“进入夜晚”和“进入白天”做成同级入口；两者返回首页，不互相自动跳转。
- [x] 只读显示来自统一时间线的技能、提名、票型、处决和更正摘要。
- [x] 首页玩家状态板显示号码、当前角色、昵称和状态图标；点卡才在说书人 Sheet 中确认生死/中毒/醉酒变更，并按结构化字段筛选该玩家的相关记录。

### 3A.1 主持辅助小工具（后续）

- [x] 首页提供`开场白`入口：可按本局在全屏 Sheet 内编辑、恢复默认或大字展示；展示不写日志、不启动计时、不发消息。
- [ ] 扩展`主持词`入口：首夜、白天、提名/投票和收尾模板均在 Sheet 内编辑、复制或全屏展示；展示不写日志、不启动计时、不发消息。
- [ ] 增加本机持久的`临时提醒`，与权威时间线分开；只有说书人显式“记录为主持备注”才进入日记。

### 3B. AI 配板

- [ ] 输入剧本、人数、座位、玩家经验和可选锁定/排除条件后，生成 3 套标记为“原型建议”的候选。当前仅有12人 Catfishing 样例与既有座位经验。
- [x] 候选按合法性、经验适配、双方发挥空间和预计节奏排序；方案差异仅作轻量约束，不使用历史配板黑名单。
- [x] 每套候选显示简短理由、风险和节奏取向；不把随机合法组合称为 AI 判断。
- [x] 支持在草稿内换角色、换座位和手动调整；候选、草稿、确认配板保持分开。重新生成与锁定/排除条件待接入。
- [ ] 将 7—15 人基础人数、开局人数修正、可追溯冲突和恶魔伪装范围抽为版本化规则包；检查只输出阻断/待选择/人工核对，不参与夜间自动结算。
- [ ] 恶魔伪装单列为建议草稿：展示三张伪装、理由与风险，可逐张替换并重新校验；不能把建议与合法性或身份发送混为一个动作。
- [x] 开局前允许持续微调。开局后通过“确认调整”追加差异事件从当前起生效，不改写既有日志或本夜队列快照。
- [ ] AI 候选、采用候选、确认配板和身份交接保持不同动作；本阶段不实现真实身份发送或玩家收件箱。

### 3C. 身份交接与官方/实体魔典协作（V1 产品边界）

- [x] 首版以线下交接为主：说书人确认配板后，按号码把实体身份牌/魔典 Token 放好；需要比划或展示时只使用本机的单人聚焦展示。
- [x] 增加`发身份`全屏二级页：同时保留“屏幕领取”和“实体抽牌”两种方式。屏幕领取默认遮住身份，点开后只展示单个玩家的对外身份和能力；实体抽牌只记录领取进度，不替代实体牌。
- [ ] 身份领取记录当前只做本机 UI 进度；后续若进入正式数据层，需要归档领取、重看和更正事件，并区分真实身份与对外展示身份（如酒鬼、疯子）。
- [x] 官方魔典同步器退出当前路线：不做半自动点击脚本、DOM 注入、WebSocket 同步、逆向接口、坐标校准或官方页面操作助手。
- [ ] 补“配板交接卡”：按座位导出或打印 `座位号 · 昵称 → 身份`，附恶魔伪装和核对状态，供说书人手动录入官方/实体魔典。
- [ ] 补“手动录入核对清单”：从官方/实体魔典回填本工具时，只提供座位、角色、昵称、状态的人工核对入口，不追求自动同步。
- [ ] 截图/OCR 暂停进入路线；未来若重新评估，也只能生成待确认草稿，人工确认前不写入本局、不改官方/实体魔典。
- [x] 不做常驻玩家端、玩家收件箱、官方魔典自动同步或官方内部接口协作；只有官方提供稳定、公开、允许的导入/导出格式时，才重新评估官方格式单向导入。

### 3D. 剧本导入与知识包（后续）

- [x] 首页提供`切换板子`全屏入口；当前局只读显示当前板子，不能原地覆盖已有配板、时间线或夜序。当前只有已核对的 Catfishing 样例可见。
- [ ] 导入 JSON 时同步建立 `ScriptDefinition + ScriptKnowledgePack` 草稿；只导入角色文本的剧本不进入可开局列表。
- [ ] 已知 `roleId` 自动关联本地版本化角色事实；未知/自定义角色必须补完阵营、夜序、开局效果、伪装范围及冲突/Jinx 覆盖后才能完成导入。
- [ ] 导入确认保存 `contentHash + rulePackVersion + coverage`；角色表、文本或顺序变化后使旧知识包失效并要求复核。
- [ ] 图标从独立素材目录按 `roleId` 解析；缺图退化为阵营 Token，不以抓取网页图片作为导入前提。

### 3E. 真实 AI API 设置（后续，未开始）

- [x] 常驻页右上角增加 AI API 设置入口，保存模型、base URL、超时、是否启用流式、最大上下文等非敏感配置。
- [x] 增加本机/后端分层的 AI Provider 设置页雏形：接入地址、模型名字、临时 API KEY、配置测试和保存动作已分开；真实后端连通性仍待接入。
- [x] 前端原型已通过 settings service 和测试保护：临时 API KEY 不写入源码、localStorage 或导出日志。
- [ ] 正式后端阶段 API Key 只走环境变量或后端密钥存储。
- [ ] AI 调用只返回候选、建议、追问和文案草稿；不能直接确认配板、修改状态、写入时间线或执行发送。
- [ ] AI 服务不可用时，夜序、投票、日志、计时、开场白和手动配板仍可用。

## 阶段 5：白天工作台与投票（投票样例已实现）

- [x] 白天技能、公开事件、提名和票型都通过统一 `TimelineEntry` 写入白天记录段；白天技能与公开事件保留发动者/关联座位等结构字段。
- [x] 白天技能在确认时冻结“按此技能结算、发动者实际身份、公开声称、目标实际身份、结果”；日记不按当前角色反推旧行动。
- [x] 每轮投票记录提名人、被提名人、门槛、逐座位举手、死亡票和 0 票；“完成本轮计票”后清空当前举手状态。
- [x] 未确认票型与技能/公开事件表单分别保存为可恢复草稿；返回首页或刷新后保留。结束今天遇到任一非空草稿时只能继续处理或明确清空，不生成票型、不写入白天行动、不处决、不自动进入夜晚。
- [x] 每轮结果只更新暂列处决、覆盖、平票或未达门槛，不修改玩家生死。
- [x] 说书人显式选择“确认处决 N 号”或“确认无处决”；仅前者追加死亡状态变更，并且只影响对应座位。
- [x] 白天结束不自动进入夜晚；说书人可继续补记或从常驻面板手动进入夜晚。
- [x] 白天页头提供可暂停、重置、刷新恢复的“私聊 → 公聊”主持节奏计时；默认 15 分钟 → 10 分钟，可分别设置为 1–180 分钟。私聊结束后由说书人显式开始公聊，两个计时归零均不结束今天、不改变投票或写入记录。
- [x] 首页“进入白天”入口只读显示同一份私聊 → 公聊计时状态；开始、暂停、重置和时长设置仍只在白天工作台，避免首页出现第二套控制器。

## 停止条件

- 如果唱片隐喻增加阅读或误触，退回当前角色卡与明确按钮。
- 如果出现第二套夜序、第二套草稿、第二套可写日志或角色 ID 规则分支，停止新增功能，先合并状态源。
- 如果“完成本轮计票”能够直接杀人、任何操作能自动进入另一昼夜，停止并恢复说书人显式确认边界。
- 连续两个阶段只增加展示/确认层而没有缩短现场操作，停止扩展。
