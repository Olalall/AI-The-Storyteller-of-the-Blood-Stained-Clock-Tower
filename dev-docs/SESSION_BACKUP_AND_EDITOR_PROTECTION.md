# 对局备份恢复与多标签页保护

实现记录：2026-09-08，仅适用于 React 新版 `AI-The-Storyteller-of-the-Blood-Stained-Clock-Tower`。2026-10-19刷新交接及跨浏览器返回保护已上线，1,537项回归、95项浏览器通过，22项单测和4项真实缓存条件跳过；浏览器含6项明确标记的合成补测，见[最新发布记录](RELEASE_2026-10-19_CROSS_BROWSER_EDITOR.md)。2026-10-16的[部署记录](RELEASE_2026-10-16.md)及下文首轮证据保留原日期。

## 使用方式

在顶部点击“备份恢复”。

1. “导出当前对局”下载当前 GameSession JSON，包含已确认记录、夜序光标以及对局中的草稿。
2. “选择备份文件”只读取和预览文件，不修改当前局。预览显示剧本、人数、开放阶段、记录和夜晚草稿数量。
3. 勾选替换确认，再点击“确认恢复”。程序先保存当前局的回退备份，再写入导入的局；随后重新打开页面，从统一存档加载。
4. 如果恢复错了，在同一入口点击“查看恢复前备份”，预览后再次确认恢复。

恢复前备份只保留最近一份；每次成功替换前都会更新。它是只读回退副本，不是第二套权威状态。导出和恢复不额外产生技能、处决或阶段推进命令。

当前支持版本 1、最多 10 MB、包含已安装剧本的 JSON 对局文件。拒绝缺失字段、重复记录 ID、错误座位、缺失夜序/光标/草稿引用及未知版本；不自动修补不可信的规则或记录。文件选择失败、取消确认或恢复前备份写入失败，都不得替换当前局。

## 多标签页

同一浏览器、同一网站地址的页面共享编辑保护。一页取得编辑权后，第二页会显示保护面板；可以导出此页副本，或在原编辑页关闭后重新打开最新局。

支持 Web Locks 的浏览器使用原生独占锁标识仍在运行的编辑页。刷新后新文档可以立即接手已结束文档的同协议租约，不依赖退出时异步清理成功；新开或复制的标签页有独立编辑身份，不能抢走仍活跃的编辑页。原生锁按文档生命周期释放，见 [Web Locks 标准](https://w3c.github.io/web-locks/)。

不支持 Web Locks 的浏览器，以及升级前未标记协议的旧页面，仍按 15 秒租约、每 5 秒检查保守处理，极端退出后可能等待约 20 秒。API 存在但建立原生锁失败时停止编辑，不按“不支持”降级。旧页面重新活动或提交时必须再次检查，不能直接写入旧内存覆盖新存档。

“重新打开最新对局”是显式放弃此页旧内存、读取最新存档；有需要时先导出此页副本。未完成保存时有浏览器离页提醒，但浏览器强制结束或系统关机不能依赖该提醒保障数据。

从浏览器返回缓存恢复时，存在未保存、待完成提交或中断内容的普通对局会保留此页内存并暂停编辑。先导出此页副本，再重新打开最新对局，避免自动刷新丢弃内存或旧内容覆盖新记录。干净页面继续读取最新存档；离页提醒只在有保存风险时监听，不作为手机数据安全的唯一保障。

## 实现边界

- `src/services/session/sessionEditLock.ts` 先取得同名原生独占锁，再用既有 IndexedDB 读写事务协调租约。只有持有原生锁且旧租约标记为 `web-lock-v1` 时可提前接手；未标记旧租约必须等待过期。事务提交前后均核对编辑权与存档原文，再调用已有 localStorage 保存入口。IndexedDB 只存租约元数据，不存游戏业务状态。
- 初始化的内存对局与保存基线来自同一次原文读取；不能先解析旧局、再读新原文作为基线。旧字段规范化不会改写这份原始字节基线。
- 租约为 15 秒，每 5 秒续期/检查。真正保存前再次核对拥有者和存档基线；检测到外部修改时停止编辑并保留此页副本用于导出。
- localStorage 仍是当前对局唯一持久化真源；新增 `botc-session-before-restore-v1` 仅保存最近一次恢复前副本，已登记架构白名单。
- 浏览器无法建立编辑保护时停止编辑并给出可恢复提示，不静默退化为无保护写入。
- 不提供跨浏览器、跨设备协作或云端实时同步；不同网站地址的数据本就由浏览器隔离。
- 不新增依赖，不修改旧 V2.5。2026-10-19已执行新版部署，本轮未调用付费 AI；下方2026-09-08首轮历史验收当时没有部署。
