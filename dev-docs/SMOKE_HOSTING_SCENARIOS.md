# 模拟主持流程验收

本文件替代“必须真实线下开一局才能发布”的硬门槛。当前项目可以没有真实桌游现场，但发布前必须通过可重复的模拟主持流程。

## 结论边界

- 不再把“真实局验证”作为 GitHub alpha / preview 发布阻塞项。
- 改为：模拟主持流程验收 + AI 质量回归 + VPS 稳定性验证。
- README、release note 和 GitHub 页面不得写“已通过真实线下局验证”。
- 推荐写法：已通过模拟主持流程验证，适合自用和早期试用；真实线下体验欢迎反馈。

## 必跑场景

### 场景 A：12 人瓦釜雷鸣完整主持链路

目标：覆盖最接近你当前使用方式的主流程。

验收路径：

1. 选择 12 人。
2. 选择瓦釜雷鸣 / Catfishing。
3. 填昵称和经验，未填经验默认标准玩家。
4. 生成 AI 配板候选，采用一套后手动换 1-2 个角色。
5. 确认开局。
6. 打开发身份，分别走“屏幕领取”和“实体抽牌记录”。
7. 进入首夜，按夜序处理至少 5 个角色。
8. 对赌徒、洗脑师、舞蛇人等复杂角色请求 AI 夜间建议。
9. 采用一条 AI 建议到草稿，但必须由说书人确认后才写日志。
10. 进入白天，启动私聊 / 公聊倒计时。
11. 记录白天技能或公开事件。
12. 完成至少 4 轮提名，覆盖暂列、覆盖、平票、死亡票。
13. 确认处决。
14. 进入第二夜，确认夜序仍按当前局角色筛选。
15. 更正一条夜间记录。
16. 结束对局、保存归档、打开历史复盘、重置游戏。

通过标准：

- AI 建议未确认前，不改变身份、阵营、死亡、毒醉、昼夜或日志。
- 所有已确认记录都能在常驻记录和日记中找到。
- 重置后玩家数量、状态、日志、昼夜、夜晚运行和白天草稿清空。

### 场景 B：7 人小局开局

目标：验证小人数 UI 和模板合法性。

验收路径：

1. 选择 7 人。
2. 选择官方基础板或任意已可开局智能板子。
3. AI 配板、确认开局、发身份。
4. 进入首夜，确认夜序只包含在场角色。
5. 记录一次状态变化并回到常驻页查看。

通过标准：

- 7 人模板不越界。
- 常驻玩家状态板不挤压、不错位。
- 状态变更只由说书人确认。

### 场景 C：15 人大局密度

目标：验证大人数下界面密度和日志可读性。

验收路径：

1. 选择 15 人。
2. 选择任意可开局智能板子。
3. AI 配板并确认。
4. 打开夜序，检查当前角色、上下位预览和 AI 建议入口。
5. 进入白天，记录至少 2 轮投票。
6. 打开日记筛选玩家和昼夜。

通过标准：

- 15 人状态卡仍可点击。
- 夜序不出现不在场角色。
- 投票票型和日记筛选可读。

### 场景 D：故障与降级

目标：验证现场不顺时仍能继续主持。

验收路径：

1. 刷新浏览器。
2. 关闭或断开 AI 后端。
3. 重启后端。
4. 缺少角色图标素材包。
5. 归档后刷新。

通过标准：

- AI 不可用时，手动记录、夜序、投票、计时、日志仍可用。
- 缺图只影响视觉，不阻塞开局。
- 归档不重复，刷新后可查历史复盘。

## AI 质量回归

每次修改 AI prompt、角色知识、智能板子包或夜间建议逻辑后，至少抽查：

- 赌徒：目标、猜测角色、正确/错误、死亡草稿提示。
- 洗脑师：疯狂要求、被洗脑角色、告知文案。
- 舞蛇人：身份交换、阵营转换、旧恶魔/新舞蛇人信息、醉酒提醒。
- 方古 / 普卡 / 诺-达鲺：死亡、跳转、延迟影响和说书人核对点。
- 红唇女郎 / 熬药女巫 / 疯子 / 麻脸巫婆：只输出建议，不自动改状态。

通过标准：

- 默认给可采用草稿，不因非关键缺项过度追问。
- 只有缺目标、缺角色、缺关键历史、发动者/目标状态冲突时追问。
- 输出必须区分：结算建议、告知玩家、可能状态草稿、说书人核对点。

## VPS 稳定性验证

VPS 自用前至少验证：

- 前端与后端端口不冲突。
- V2.5 与新辅助工具目录、端口、进程名分开。
- AI Key 只在后端环境变量或密钥文件中，不进前端和 Git。
- 归档目录可读写，重启后归档仍可查。
- PM2 / systemd 或手动启动方式明确。
- 重启后前端能显示 AI 可用 / 不可用状态。

## 发布措辞

允许：

> 已通过模拟主持流程验证，适合自用和早期试用；真实线下体验欢迎反馈。

禁止：

> 已通过真实线下局验证。

> AI 会自动正确结算全部规则。

> 可替代官方魔典。
