# 无人推进项目：多板子、7-15 人、真实 AI 准入

状态：设计冻结，等待按任务索引执行。  
目标：让后续开发可以无人连续推进，但只推进已经写清边界的本地工程任务；遇到真实外部服务、部署、凭证、产品路线决策时自动停止。

## 1. 这不是无限授权

无人推进不是“让 agent 想做什么就做什么”。它只允许按 `UNATTENDED_TASK_INDEX.md` 中状态为 `Ready` 的任务顺序推进。

允许自动进入下一阶段的条件：

1. 当前阶段验收命令全部通过。
2. 当前阶段更新了任务索引和人类变更记录。
3. 下一阶段状态是 `Ready`。
4. 下一阶段不触发任何停止条件。
5. 没有需要你现场判断的产品取舍。

必须停止的情况：

- 下一阶段是 `Blocked` 或 `Needs User Review`。
- 需要真实 API Key、付费模型调用、VPS 写入、部署或生产数据。
- 需要新增数据库、ORM、账号、玩家端、官方魔典同步器。
- 需要改变说书人权威边界。
- 需要复制旧项目大块代码。

## 2. 当前可无人推进到哪里

在不需要你盯屏的前提下，当前可以安全推进到：

```text
智能板子基础架构
  -> Catfishing 智能板子包迁移
  -> Catfishing 规则调研与角色验收
  -> 模板库与随机候选引擎
  -> 7-15 人开局数据流和 UI
  -> 身份交接与重置后引导打通
  -> AI 请求/结果合同与 mock/fake adapter
  -> 外部审查包
```

不能无人越过：

```text
真实 AI 付费调用
VPS 生产写入/部署
新增数据库/ORM
常驻玩家端/收件箱
官方魔典同步器
自动规则引擎
```

## 4. 防跑偏规则

### 板子

- 可玩板子必须是智能板子包。
- 新增板子先规则调研，再进入开局列表。
- `needs-review` 的角色可以显示，但不能给高置信 AI 建议。
- 中文名只做展示，不做主键。

### 开局

- 开局流程固定：选择人数 -> 选择板子 -> 昵称/经验 -> AI 配板 -> 手动调整 -> 确认开局 -> 可选身份交接 -> 手动首夜。
- 上一局只能复用昵称和经验。
- 未标注经验默认为标准玩家。
- 确认开局不自动进入夜晚。

### AI

- AI 输出只能是候选、提醒、草稿或润色。
- AI 不直接写权威状态。
- 真实 AI 必须走后端代理。
- 前端不得保存明文 API Key。
- 默认按问题最小化上下文。

### 技能结算

- 手动记录永远可用。
- AI/规则建议只填草稿。
- 身份、阵营、状态变化必须由说书人确认后追加事件。
- 当前夜序快照不因身份变化自动回滚或重排。
- 不为每个角色在 UI 里写特殊 if。

### 旧项目参考

允许参考：

- 旧项目犯过的错误。
- 业务字段和流程经验。
- 验收场景。

禁止复制：

- 巨型 HTML。
- 巨型 server。
- 多套状态源。
- 角色 ID 自动规则状态机。
- WebSocket/官方魔典同步方案。

## 5. 文件预算

- 入口文件建议不超过 120 行。
- 前端业务组件建议不超过 300 行。
- 共享 UI 组件建议不超过 220 行。
- 后端业务文件建议不超过 180 行。
- domain 规则/板子数据文件如果天然较长，必须按 roles、night-orders、templates、rules 拆分。

超过预算前必须拆分；不能靠注释解释“大文件合理”。

## 6. 每阶段验收

每阶段必须至少完成：

```powershell
npm run check
```

涉及后端 runtime 时追加：

```powershell
npm run test:server
npm run smoke:backend
```

涉及浏览器流程时追加相关 E2E 或手动浏览器 smoke 证据。

每阶段完成后必须更新：

- `dev-docs/UNATTENDED_TASK_INDEX.md`
- `dev-docs/HUMAN_CHANGELOG.md`
- 必要时更新 `dev-docs/development-plan.md`

## 7. 交付格式

每阶段最终汇报必须包含：

1. 完成了什么。
2. 用户能看到什么变化。
3. Before / After。
4. 触及文件。
5. 验证命令和结果。
6. 未做内容。
7. 是否触发停止条件。
8. 下一阶段是否可自动继续。

## 8. 当前建议

下一次真正开始无人推进时，从 `UNATTENDED_TASK_INDEX.md` 的阶段 10.1 开始：建立 `domain/scripts` 类型和 registry。不要先做真实 AI、VPS 或新 UI 大改。
