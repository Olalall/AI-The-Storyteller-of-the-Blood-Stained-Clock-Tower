# 六昼夜触控模拟验收

日期：2026-09-08。适用于 React 新版。本地生产构建、Chromium 手机/平板模拟，不等于实体设备或数小时持续运行验收。

## 本轮修复

玩家状态弹窗保持打开时，确认后的存储失败原先只在 App 顶部显示。Radix 弹窗会遮挡并从无障碍树隐藏该区域，因此玩家状态面板里虽然显示了内存中的新状态，用户却可能看不到“尚未保存”的提示。

`SessionSaveNotice.tsx` 现在在失败发生时打开最上层的嵌套弹窗，直接提供重试和导出。关闭提示后仍保留原有失败条，不清空内存、关闭玩家面板或重置对局。重试成功后失败提示消失，玩家面板和已确认内容保留。弹窗使用独立的网格布局，避免依赖 Portal 外的 app-frame 容器导致窄屏按钮拥挤。

## 可重复场景

`tests/load-performance/long-session.spec.ts` 在 390×900 和 820×900 下启用 hasTouch/isMobile，并通过 tap 执行主要操作：

1. 12 人确认配板，连续处理 6 夜、6 天；有 6 轮投票、2 次确认处决、4 次无处决。
2. 已死亡玩家的夜晚适用性，由脚本模拟说书人明确点击“不适用”；绝不绕过该确认直接结算。
3. 第 2 夜保留未确认输入后刷新，核对完整存档、夜序和当前处理位置仍一致。
4. 第 3 天断网填写投票草稿，再尝试断网刷新；恢复网络后完整草稿一致，再由点击确认形成票型记录。
5. 第 4 天模拟浏览器存储空间不足，在玩家状态弹窗确认中毒；最上层错误可见，旧存档不变，导出包含内存新记录，重试成功后与导出内容完全一致。
6. 最终核对 12 个已关闭阶段、6 份夜序、无重复记录 ID、夜晚记录总数、2 次处决和3条状态变更；刷新后归档，归档中的整份 session 与当前局完全一致。

初始测试修正了两处驱动假设：恢复入口包含“第N夜/天”副标题；死亡玩家需要人工适用性确认。这两处不是产品故障。六昼夜是功能连续性与中断恢复验证，不是胜负规则正确性或真实时长压力测试。

## 运行方法

```powershell
npm run build
npx playwright test --config playwright.load.config.ts --grep 'six days|保存失败可见|纯记录模式主干' --workers=2 --output .codex-artifacts/long-session/verified
```

只在本地隔离浏览器上下文使用测试局；不访问真实用户存档、后端归档或模型。

## 真实设备仍需验收

当前结果不能覆盖 Android/iPad 系统键盘、真实分屏与触控误触、后台数小时后恢复、系统回收标签页、VPS 弱网和部署后版本缓存。最新代码尚未部署到设备可访问的环境。

真实设备上应另外检查：弹窗内按钮可触达；草稿填写后切后台再返回；刷新前后的已确认记录一致；断网时首次加载新剧本失败可返回；存储失败时先导出再处理。至少用一台实际手机和一台实际平板，记录设备、系统、浏览器及构建版本。


## 验证结果

- 单元测试：915 项通过，3 项真实模型测试跳过；lint、TypeScript/生产构建、架构检查、diff 空白检查通过。
- 六昼夜触控模拟：390px、820px 两项均通过，合计运行约 1.2 分钟（并行运行，不能当作实际长局时长）。两局均完成 12 个关闭阶段、6 轮票型、2 次处决、4 次无处决和3条状态变更，最终归档完整匹配。
- 相关既有浏览器回归：完整配板到归档主干、390px/1440px 保存失败导出与重试，共3项通过。本轮合计5个不同场景通过。
- 最终六昼夜截图及通过状态位于 `.codex-artifacts/long-session/passed`；既有回归结果和截图位于 `.codex-artifacts/long-session/verified`。390px 与820px 的保存失败嵌套弹窗已实际查看，按钮均可见。
- 断网时浏览器内部错误页不具备 origin 存储，因此测试初始化只在能访问存储的页面播种测试局；应用代码的 pageerror 零错误断言没有过滤或放宽。归档胜方选项含“说书人确认”辅助文字，测试按完整操作名的前缀定位。

最初失败证据保留在 diagnostic/accepted/final 等目录；不能把这些失败轮次当作通过结果。最终以 passed 两项、verified 中另外3项通过和上述单测结果为准。
