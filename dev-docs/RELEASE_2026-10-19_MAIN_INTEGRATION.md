服务器既有的公开分享开关会让新后端忽略固定 API 配置。首次切换在配置状态检查时失败，程序已自动回滚到当次备份的正常版本，未恢复或覆盖旧数据。

公开模式保留归档隔离、请求大小限制、限流和跨站保护。只有服务端 AI 配置完整且设备访问密钥去空白后至少 32 字符时，无覆盖配置的受邀请求才可使用固定 API，并禁止上游重定向。显式提供的 BYOK 配置继续经过原有允许列表校验，非法配置不能回退使用服务器密钥。连通测试统一采用同一配置判断。

## 公开隐私边界

公开源码、测试与文档只使用虚构占位配置。实际 API 上游地址、模型配置、密钥、访问口令、个人域名、IP、云实例、机器路径和对局数据不进入发布内容。公开审计移除个人定值，失败时只输出问题类别及文件行号；密钥和原始匹配全文均不打印。

既有 Git 历史与本轮待发布文件需要分开检查。把当前文件改成示例不能删除此前提交或 PR 缓存里的内容；清理历史需要明确范围和单独操作，不能以最新文件已脱敏代替历史清理完成。
