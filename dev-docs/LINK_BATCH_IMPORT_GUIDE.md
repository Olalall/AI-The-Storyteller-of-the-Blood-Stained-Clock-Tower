# 从网页链接批量增加板子

适用于大量网页链接或在线剧本库。本项目当前开局列表来自已注册的智能板子包，网页里尚无“粘贴任意链接立即入库”的入口。现有 `scripts/scout-script-collection.mjs` 只能采集特定 collection 页的 `/script#data=` 链接，不能冒充任意网站通用导入器。

可以一次提供完整的链接清单，由开发流程批量采集和去重，再分批验收。共享角色板子不再按十板划分固定批次；一次扫描全库，集中核对重复角色事实，将通过的普通板子合批处理，新角色与冲突版本另排队。没有实际链接时不猜板子名单，也不把搜到的板子自行加入正式开局列表。

## 先整理全库，复用角色验收

Clocktower Wiki已锁定的两份缓存可以直接生成下一批清单，无需逐板填写原文路径、来源、角色来源版本和夜序：

```text
npm run plan:scripts -- locked-cache new-intake-plan 100
npm run prepare:scripts -- new-intake-plan/batch.json new-drafts
```

第一步不联网、不注册板子。它扫描全部记录，保留完整原文与作者元数据，输出逐板`intake-plan.json`、按角色身份／原文／类型归组的`role-review-groups.json`，以及供原批量工具使用的`batch.json`。最后一个数字只限制本次生成多少草稿，不限制全库扫描；默认100，不保证能找到100个齐全候选。完整JSON缺失、重复原文、未知角色、重复角色、夜序版本或特殊开局问题分别列出。

复用来自已确认的原文映射和完整共享角色指纹；原文字节或共享定义变化后，旧映射会失效。相同技能原文、名称和类型可以为作者的不同角色ID复用对应关系，主键仍是共享库的稳定英文ID。只有名称和类型相同时，只提出未确认的身份候选，明确要求核对身份和技能原文；不会按同名自动认定技能正确。别名、译文和旧版差异集中核对一次，关联全部受影响板子，不逐板重复查同一角色。

原文提示语、作者夜表、相克和额外规则不属于可自动复用的角色事实；仍需板子级检查。角色来源存在歧义时，只复用已经确认且与当前官方夜表对应的固定来源，不任意挑一个旧版本。生成的`intakeReview`依赖会随批量工具保留到`source-lock.json`，草稿、模板、作者规则和身份候选都不会自动变成已确认。

后续验收以差异安排：每板均检查原文、模板、人数、伪装和两种夜序；整批做一次完整回归与构建，新增／变化的技能和组合做针对性浏览器及真实AI测试。重复角色不重做整套人工验收，抽测不冒充所有使用场景均已覆盖。最终一次合批发布，保留旧局及数据。

## 两类板子分开处理

- 已有角色的新组合：复用现有角色知识和输入说明，重点检查作者版本、相克、夜序、人数修正、伪装和开局模板。
- 含新角色或自制规则：先核对作者或发行方资料，补齐技能原文、输入数量、夜序、信息告知和特殊判定；未核实的先留作候选，不标成可智能开局。

## 每批实际步骤

多个已有角色板子可以共用一次角色库加载和验收上下文：

```text
npm run prepare:scripts -- intake/batch.json new-batch-directory
```

`batch.json` 的结构为 `{ "scripts": [ ... ] }`，每项沿用下方单板输入，并增加 `sourceFile`（相对清单目录的原文路径）和可选的 `fillTemplateGaps: true`。原文须位于清单目录内，不能通过绝对路径、`..` 或目录链接跳出。工具不下载任意链接、不执行原文脚本；先核对原始字节 SHA256、角色数量、稳定 ID 和团队。重复 ID、已注册板子或重复原文会拒绝覆盖；单项来源或规则错误另列原因，其余草稿继续处理。

自动补缺复用共享角色和已确认模板中的人数修正事实，用现有领域函数计算人数，并将同一角色的修正选项归到一个规则下；不能把旧板各自的规则 ID 当成需要同时叠加的多个能力。除普通单恶魔模板外，现支持卡扎力无初始爪牙、召唤师无初始恶魔、军团多数重复角色、堤丰额外爪牙与连续邪恶座位，以及小怪宝无恶魔座位的独立候选。每种候选仍由生产配板规则检查，并保持未确认；板子级原文、相克和规则差异仍需核对。缺少角色、合法伪装、人数选项或足够模板时会列缺项，不会凑数上架。

小怪宝新模板明确选择 `lilmonsta-extra-minion/extra-minion-no-demon`，不发普通恶魔伪装；其照看者和可选死亡作为无座位步骤记录。这个规则选择是显式启用标记，旧模板和旧局不会因升级被重新解释。召唤师和小怪宝的无恶魔开局不预分配提线木偶：当前相克要求木偶在恶魔出现后入场并邻座，不能沿用原文中的旧相克凑人数。堤丰检查邪恶连续且两侧邪恶，不要求几何正中央。

历史角色 ID 只在导入阶段提示对应当前稳定 ID，例如 `plague_doctor`、`ban_shou_ren` 和旧中文拼音 ID；来源原文、旧板 ID 和旧局快照保持。提示仍需核对身份、类型和完整定义，不能仅凭别名自动批准旧能力原文。

每个齐全草稿都调用实际生产配座、配板确认及首夜／后夜队列代码，检查全部模板和全部人数档；通知爪牙这类系统投递按其来源角色核对夜序。这里检查的是生成队列，不等于完整执行两夜。输出逐板保存 `definition.json`、`index.ts`、`review.json`、原始 `source.json` 和 `source-lock.json`，整批另有 `batch-review.json`。作者的 `_meta.state`、`_meta.states` 以及完整元数据都会保留。

整批报告将相同完整角色定义、原能力文本和团队分组，供规则复核与 AI／浏览器抽测安排使用。它不把分组数量当成技能覆盖率，也不自动宣布 AI 或浏览器通过。来源、作者特殊规则、当前相克、角色变化与板子特有组合仍逐板检查；高风险实际操作按机制选择代表题，保留逐板覆盖和未覆盖项。

工具退出码为 0 表示自动检查齐全，2 表示至少一板失败或缺模板，1 表示清单／输出等致命错误。无论退出码如何，草稿仍是 `needs-review`、模板仍为 `verified: false`，不会改注册表、既有包、对局或私人配置。最终注册、生成清单、完整测试、隐私扫描和部署按整批各做一次；中间发现新问题时才重跑受影响检查。

已有角色可先使用离线准备工具：

```text
npm run prepare:script -- candidate.json new-draft-directory
```

输入包含 `scriptId`、`displayName`、`source`（原文公开链接、版本、SHA256和核对日期）、`roleRefs` 和板子特有 `setupRules`。可用 `templateSources` 限定从哪些已入库板子复用配板模板，也可明确提供 `setupTemplates`。普通角色引用直接填写稳定英文ID；有歧义时使用 `{ "id": "...", "sourceId": "...", "sourceVersion": "sha256:..." }`。冲突会列出已知来源，不能按中文同名猜角色。

工具从独立 `src/domain/scripts/role-library/` 读取既有定义，生成 `definition.json`、`index.ts` 和 `review.json`。不复制技能实现、不修改页面、不覆盖已有目录，也不修改注册表。核心默认定义与其他来源先对齐图标路径；同版资料共享，变体保留来源/版本。

已经注册的薄板包仍能提供配板模板，角色来源继续指向原共享定义；不能把薄板的新名称当成新的角色版本。连续准备下一批时，无需给薄板补一个重复的 `roles.ts`。

生成资料同时保存每个完整角色定义的 SHA256 指纹。注册后生成清单与构建会核对指纹；共享定义发生变化时必须重新准备并人工核对，不能继续用旧来源版本标签悄悄加载新技能。指纹检查属于发布检查，不会用新版资料重写旧局快照。

当前官方默认角色可以复用项目已核实的夜表；自制角色或非默认变体必须提供已经核对的 `nightOrders.firstNight` 和 `nightOrders.otherNight`。自制能力占用官方ID会被拒绝，应先分配独立稳定ID并补支持。官方角色别名只作身份归一，不能把同名自制能力当作官方技能。

可复用模板会重新检查人数构成、板内角色与伪装，最多生成每个人数所需的候选数量；不足部分在 `missingTemplateCounts` 中列出。所有模板仍为 `verified: false`，板包为 `needs-review`。结构合法不代表组合平衡或特殊规则已核实。

核对草稿与特殊组合、补齐缺项并通过回归后，再将目录放入 `src/domain/scripts/packs/<scriptId>/`，从 `allPacks.ts` 注册生成模块导出的板包，并运行 `npm run generate:script-manifest` 和完整检查。注册前不能把草稿当成可开局板子；已有会话继续使用自己的快照。

1. 保存原始链接、板子名、作者、版本和可下载的 JSON，计算内容哈希。
   新接入板子的 `source.json` 保留下载原文的完整字节，SHA256 和字节数按原始文件计算；逐条在 `.gitattributes` 为已核对的原文路径设置 `-text`，禁止 Git 在检出或提交时转换换行。不要格式化原文或统一 LF/CRLF，否则会破坏 `source-lock.json` 的来源校验。已有板子只有复现字节校验问题并与既有锁匹配后，才恢复原文并逐条固定路径；不使用全库通配或统一换行。
2. 按内容和稳定 ID 去重；同名不同版保留差异。自制角色与官方 ID 冲突时先处理命名，不能覆盖现有角色规则。
3. 对照作者夜表和最新官方角色资料，检查首夜、后续夜、相克、人数构成与恶魔伪装。
4. 生成板子包草案，覆盖 7–15 人的合法模板；检查多目标、可选不发动、角色选择、复活、毒醉及改身份等实际输入。
5. 通过人数、夜序、输入、保存恢复和关键规则回归；新增高风险技能另抽取真实 AI 题，人工检查原始回答。
6. 将通过的板子注册到统一目录并重新生成清单，测试后分批发布。既有对局继续使用原配板和夜序快照。

大量入库时，来源采集和结构检查可以批量跑。技能判定不能仅凭“JSON 能解析”或“资料齐全”判作正确。验收结果应区分：结构通过、规则资料已核对、真实 AI 抽测通过和未覆盖的交互。

## 本轮工具与复用验证

当前共享索引来自 138 个已注册板包、3,662 条角色引用，归一后有 705 个角色 ID，其中 131 个核心定义有明确优选。迁移前后全部原始和正规化板包逐项相同，夜序和模板保持；这组数量不表示全部角色组合已通过实战。

准备工具已检查来源版本消歧、未知角色拒绝、自制角色显式夜表、重复角色与非法伪装过滤、生成模块实际加载、角色定义指纹变化和已有目录保护。生成目录仍为未注册草稿，不会自动把链接库中的板子上架，也不会改变现有对局。

本轮最终完整检查有 2,660 项测试通过、11 项条件跳过，54 项生产浏览器检查通过。ego-browser 完成 7、9、12、15 人四局，每局三夜三昼，另有不计入整局的专项片段；真实 AI 用 33 次实际尝试覆盖 16 个局部语义题，保留四次原始失败及复测。本轮验收已完成；发布状态以 GitHub 合并记录和部署回执为准，详见[本轮记录](RELEASE_2026-10-21_SHARED_ROLES.md)。这些结果不替代下一批板子的来源、特殊组合、模板和人工操作验收。

具体项目合同见 [多板子架构](SCRIPT_ARCHITECTURE_PLAN.md)、[角色验收清单](SCRIPT_ROLE_ACCEPTANCE_CHECKLIST.md)、[规则调研协议](RULE_RESEARCH_PROTOCOL.md)和[批量导入计划](UNATTENDED_MASS_SCRIPT_IMPORT_PLAN.md)。本轮没有新增任意 URL 下载接口、开放上传或未经指定的板子。
