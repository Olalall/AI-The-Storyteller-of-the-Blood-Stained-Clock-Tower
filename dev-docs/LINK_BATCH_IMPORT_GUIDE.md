# 从网页链接批量增加板子

适用于大量网页链接或在线剧本库。本项目当前开局列表来自已注册的智能板子包，网页里尚无“粘贴任意链接立即入库”的入口。现有 `scripts/scout-script-collection.mjs` 只能采集特定 collection 页的 `/script#data=` 链接，不能冒充任意网站通用导入器。

可以一次提供完整的链接清单，由开发流程批量采集和去重，再分批验收。数量不要求一次手工填写完；通常每批约十个，方便发现问题后定位和回退。没有实际链接时不猜板子名单，也不把搜到的板子自行加入正式开局列表。

## 两类板子分开处理

- 已有角色的新组合：复用现有角色知识和输入说明，重点检查作者版本、相克、夜序、人数修正、伪装和开局模板。
- 含新角色或自制规则：先核对作者或发行方资料，补齐技能原文、输入数量、夜序、信息告知和特殊判定；未核实的先留作候选，不标成可智能开局。

## 每批实际步骤

已有角色可先使用离线准备工具：

```text
npm run prepare:script -- candidate.json new-draft-directory
```

输入包含 `scriptId`、`displayName`、`source`（原文公开链接、版本、SHA256和核对日期）、`roleRefs` 和板子特有 `setupRules`。可用 `templateSources` 限定从哪些已入库板子复用配板模板，也可明确提供 `setupTemplates`。普通角色引用直接填写稳定英文ID；有歧义时使用 `{ "id": "...", "sourceId": "...", "sourceVersion": "sha256:..." }`。冲突会列出已知来源，不能按中文同名猜角色。

工具从独立 `src/domain/scripts/role-library/` 读取既有定义，生成 `definition.json`、`index.ts` 和 `review.json`。不复制技能实现、不修改页面、不覆盖已有目录，也不修改注册表。核心默认定义与其他来源先对齐图标路径；同版资料共享，变体保留来源/版本。

生成资料同时保存每个完整角色定义的 SHA256 指纹。注册后生成清单与构建会核对指纹；共享定义发生变化时必须重新准备并人工核对，不能继续用旧来源版本标签悄悄加载新技能。指纹检查属于发布检查，不会用新版资料重写旧局快照。

当前官方默认角色可以复用项目已核实的夜表；自制角色或非默认变体必须提供已经核对的 `nightOrders.firstNight` 和 `nightOrders.otherNight`。自制能力占用官方ID会被拒绝，应先分配独立稳定ID并补支持。官方角色别名只作身份归一，不能把同名自制能力当作官方技能。

可复用模板会重新检查人数构成、板内角色与伪装，最多生成每个人数所需的候选数量；不足部分在 `missingTemplateCounts` 中列出。所有模板仍为 `verified: false`，板包为 `needs-review`。结构合法不代表组合平衡或特殊规则已核实。

核对草稿与特殊组合、补齐缺项并通过回归后，再将目录放入 `src/domain/scripts/packs/<scriptId>/`，从 `allPacks.ts` 注册生成模块导出的板包，并运行 `npm run generate:script-manifest` 和完整检查。注册前不能把草稿当成可开局板子；已有会话继续使用自己的快照。

1. 保存原始链接、板子名、作者、版本和可下载的 JSON，计算内容哈希。
2. 按内容和稳定 ID 去重；同名不同版保留差异。自制角色与官方 ID 冲突时先处理命名，不能覆盖现有角色规则。
3. 对照作者夜表和最新官方角色资料，检查首夜、后续夜、相克、人数构成与恶魔伪装。
4. 生成板子包草案，覆盖 7–15 人的合法模板；检查多目标、可选不发动、角色选择、复活、毒醉及改身份等实际输入。
5. 通过人数、夜序、输入、保存恢复和关键规则回归；新增高风险技能另抽取真实 AI 题，人工检查原始回答。
6. 将通过的板子注册到统一目录并重新生成清单，测试后分批发布。既有对局继续使用原配板和夜序快照。

大量入库时，来源采集和结构检查可以批量跑。技能判定不能仅凭“JSON 能解析”或“资料齐全”判作正确。验收结果应区分：结构通过、规则资料已核对、真实 AI 抽测通过和未覆盖的交互。

## 本轮工具与复用验证

当前共享索引来自 138 个已注册板包、3,662 条角色引用，归一后有 705 个角色 ID，其中 131 个核心定义有明确优选。迁移前后全部原始和正规化板包逐项相同，夜序和模板保持；这组数量不表示全部角色组合已通过实战。

准备工具已检查来源版本消歧、未知角色拒绝、自制角色显式夜表、重复角色与非法伪装过滤、生成模块实际加载、角色定义指纹变化和已有目录保护。生成目录仍为未注册草稿，不会自动把链接库中的板子上架，也不会改变现有对局。

本轮最终完整检查有 2,660 项测试通过、11 项条件跳过，54 项生产浏览器检查通过。ego-browser 完成 7、9、12、15 人四局，每局三夜三昼，另有不计入整局的专项片段；真实 AI 用 33 次实际尝试覆盖 16 个局部语义题，保留四次原始失败及复测。本轮验收已完成；发布状态以 GitHub 合并记录和部署回执为准，详见[本轮记录](RELEASE_2026-10-21_SHARED_ROLES.md)。这些结果不替代下一批板子的来源、特殊组合、模板和人工操作验收。

具体项目合同见 [多板子架构](SCRIPT_ARCHITECTURE_PLAN.md)、[角色验收清单](SCRIPT_ROLE_ACCEPTANCE_CHECKLIST.md)、[规则调研协议](RULE_RESEARCH_PROTOCOL.md)和[批量导入计划](UNATTENDED_MASS_SCRIPT_IMPORT_PLAN.md)。本轮没有新增任意 URL 下载接口、开放上传或未经指定的板子。
