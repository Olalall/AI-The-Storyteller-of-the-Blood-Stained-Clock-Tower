# 魔典模式的边界

> 写于 2026-08-05，随 G1 落地。这份文件回答同一个问题的七个变体：
> **加了一张电子魔典之后，这个工具还是不是原来那个工具？**
> 结论是「是」，但只有在下面这些线不被越过的前提下才成立。

---

## 一、魔典模式没有改变产品定位

这个工具的定位是**说书人的笔录本**，不是游戏引擎。加入电子魔典没有动摇这一条，
因为魔典在这里是一块**显示面**，不是一台推演机：

- 它不判定任何事。处决门槛照存活数算出来并显示，但是否处决仍由说书人按下。
- 它不自动结算。夜间能力的结果由说书人裁定后录入，魔典只是把录入的结果画出来。
- 它不推进相位。黄昏、黎明、进入白天都仍然是交接卡上的一次显式动作。
- 它不产生玩家可见面。魔典画在说书人自己的设备上，没有任何网络对端。

一句话检验：**把屏幕关掉，这局还能照常进行**。魔典模式必须始终满足这一条。

## 二、两种模式是同一条数据路径

`hostingMode` 是**出处元数据**，不是行为开关。

它记录「这局当时是怎么主持的」，因为归档回放需要它：没有它，一局纯记录模式的
对局会被渲染成一张看起来很完整、实则大半没人录过的魔典，而
「纯记录模式下本来就没记标记」会被误读成「说书人漏记」。

但它**绝不能**成为分支条件。这条由 `scripts/verify-architecture.mjs` 的
`hosting-mode-not-behavioural` 规则强制：`src/features/*/state/**` 下任何读取
`state.hostingMode` 的代码都会让 CI 失败。允许读它的只有三处，且都不是 reducer：

1. 视图层——决定渲染环还是渲染列表；
2. 归档与复盘展示——说明这局当时是怎么主持的；
3. AI 上下文——说明局面完整度。

**为什么这条这么硬**：一旦 reducer 读它，两套数据模型会在几周内长出来，
而它们的差异会藏在几十个 `if` 里。到那时「切换模式」不再是换一个视图，
而是换一个程序，归档也就不再能忠实回放。

## 三、遮蔽是模型级的，不是 CSS

纯记录模式下屏幕一次只暴露一个座位，被瞄一眼损失有限。魔典模式下一屏就是
全部十几个身份加全部标记——被任何一个玩家看到一眼，整局直接结束。
**这是质变，不是量变。**

因此：

- 遮蔽决定「渲不渲染」，不是「显不显示」。CSS 覆盖挡不住截屏、屏读器和 devtools。
- 默认级别是 L1（席位视图），不是 L2。默认掀开等于「递给玩家看之前必须记得盖上」，
  那是一个迟早会忘的动作。
- 标记的 label 在 L1 下不进 DOM。「僧侣保护」暴露场上有僧侣及其今晚保了谁，
  「红鲱鱼」暴露占卜师及其误导对象，「是酒鬼」直接暴露一个玩家的真实身份。
  L1 只渲染无字圆点与计数。
- 自动机制只朝更遮蔽的方向走：页面隐藏、失焦、90 秒无操作一律回落 L1，
  且永不自动升到 L2，已盖成 L0 的永不被自动掀开。

### 一个明确的例外，以及它为什么不是先例

「投屏 / 给单个玩家看」的全屏遮蔽层（现有 `PrivateRevealOverlay`、计时器投屏）
是**同一台设备上的临时覆盖层**，不是玩家端：没有第二个设备，没有网络传输，
没有任何东西离开这台机器。

把它写在这里，是为了防止将来有人拿它当「已经有玩家可见面了，做个玩家端也不过分」
的先例。玩家端的红线不在「屏幕上有没有给玩家看的东西」，而在
**有没有第二个对端**。前者一直有，后者一次都不会有。

## 四、魔典上的每一次手势恰好一条记录

G2 允许在魔典上直接改状态之后，这条成为核心不变量：一次手势产生的
`after` 与 `before` 之间的差异字段集，必须是那次操作声明的字段名的字面子集。

原因是审计链的可信度。魔典的操作又快又多，如果一次点击顺手改了两个字段，
复盘时没有任何办法分辨哪一个是说书人的本意。

配套的是：无回执的静默写入数必须为 0。魔典上每一次落账都要有一次可见的回执，
以及 3.5 秒内的即时撤销——撤销的实现是追加一条更正记录，不是回滚，
因为已经发生过的事不该从档案里消失。

## 五、工具成为唯一事实来源的那一刻，耐久性就不再可选

G1 的魔典是只读的，工具还不是唯一事实来源，丢了存档最多丢一份笔记。
G2 一旦允许在魔典上落账，说书人就会停止在别处记录，此后丢数据等于整局报废。

所以耐久性闸门排在 G2 **之前**，不是之后：主副本之外轮转最近 5 份快照、
启动时提议恢复、多标签页单实例锁、导出 JSON 常驻可达、破坏性操作先存快照。

## 六、降级的摩擦故意大于升级

数据层面降级是绝对安全的——一个字段都不删，切回来全部还在。
风险是认知性的：说书人切回纯记录后可能仍以为工具在替他记，
于是既没在实体魔典上补、也没在工具里点，两边都空。

所以升级一点即可，降级要一次二次确认外加一张可抄的完整清单，
主动作还是「留在魔典模式」。降级后也不真的把状态藏起来——
两种模式的信息可达性差异应当是「密度和交互成本」，不是「有和无」。

## 七、缺素材时魔典必须仍然完整可用

无角色图标时，魔典要能以「角色中文名文字 Token」完整工作。

这不只是可用性要求，更是许可上的保险：它证明本工具的功能不依赖任何
受版权保护的素材。角色图标始终是可选的增强，不是运行的前提。
