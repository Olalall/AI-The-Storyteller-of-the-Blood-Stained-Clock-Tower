# 夜晚收尾清单与手动状态待办

实现记录：2026-09-08，适用 React 新版。2026-10-16 已通过回归并部署，见[部署记录](RELEASE_2026-10-16.md)；下文首轮证据仍保留原日期。

## 使用方式

夜晚底部“检查并关闭”打开收尾清单。未处理项包括暂缓和待核对；点击“查看N号”回到该项预览，原处理光标不变，随后使用现有“处理N号”显式切换。

确实无需处理时，填写原因再确认“本夜不处理”。这使用已有 skipped 状态，保留草稿与原因，不写技能确认记录，不修改适用性。不处理项单独折叠显示；回到该项后可“恢复处理”。有未提交原因时不能关闭本夜。仍有未处理项目时允许说书人确认关闭，并保留它们的真实状态；不会进入白天。

顶部“状态待办”在本局和各工作台均可用。从已确认夜晚记录选择来源、玩家和待办内容，点击“确认添加待办”。待办内容由说书人明确填写，不从 AI 自由文本或角色 ID 推断。

“处理状态”打开现有玩家状态面板，只支持该面板已有的生死、毒醉等状态操作。点击“确认状态”且命令被接受后，状态事件与待办完成同时更新。打开、取消、陈旧状态提交均不能完成待办。若无需变更，填写原因并确认；原来源和处理结果保留。来源若已有更正，详情中提示重新核对。

本轮不实现身份、阵营更改的待办执行器，也不把玩家状态面板扩充成自动规则引擎。相关变更继续使用已有人工流程。

## 确认后的快捷入口与来源更正

夜间工作台显示本夜最近一条已确认记录。点击旁边“添加状态待办”，自动选中该记录并展开添加表单；确认并进入下一位后，来源仍是刚才的记录，绝不把待办绑定到下一位的未确认草稿。座位和待办内容不自动推断，打开或取消不写状态。遮蔽时隐藏此入口。

待办来源经过多次更正时，按明确的 correctionOf 链找到最新版本，只接受同一夜晚、同一唤醒项的更正。待办显示显眼提示，展开“核对更正前后”查看原文和最新更正。已处理项也计入来源更正提示，但不自动改回玩家状态或重开待办。

添加表单中被更正的旧来源标记为不可选；如果填写期间来源发生更正，提交被拒绝，必须明确选择最新记录。旧待办仍保留最初来源，不偷偷迁移。

## 数据与权限

- GameSession 新增可选 `stateFollowups`；旧存档缺省视为空清单，不新增持久化 key，不参与玩家状态投影。
- 每个待办绑定一条已确认 night_action 和一个有效座位；记录 ID、处理说明、时间和完成状态事件 ID。备份导入验证引用及重复 ID。
- `confirm-player-state-change` 可携带 followupId；仅在待办未处理、座位匹配且状态更新通过原有并发校验时原子完成。
- 隐私遮蔽时收尾清单隐藏角色与原因，状态待办隐藏详情。AI、预览和导入都不自动执行待办。
- 已完成待办保留处理信息；同一来源后续更正不会自动撤销已确认状态，需要说书人另行核对。
- 关闭夜晚会保留未完成待办并显示数量提醒；本局备份可带走待办，不承诺赛后归档展示待办。
