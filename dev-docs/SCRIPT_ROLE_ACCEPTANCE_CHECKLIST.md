# 智能板子与角色验收清单

状态：设计冻结。  
用途：每接入一个新板子时逐项打勾，避免多板子扩展变成架构债。

## 1. 板子级清单

- [ ] 已记录板子名称、作者、版本、来源、内容哈希。
- [ ] 已确认适用人数。
- [ ] 已确认角色清单完整。
- [ ] 已确认首夜顺序。
- [ ] 已确认其他夜顺序。
- [ ] 已确认 setup 规则和人数修正。
- [ ] 已确认恶魔伪装来源和数量。
- [ ] 已确认每个人数至少有可用模板。
- [ ] 已标记规则知识状态。
- [ ] 已写 `acceptance.md`。
- [ ] 已通过项目验证命令。

## 2. 角色级清单

每个角色都必须确认：

- [ ] 稳定英文 ID。
- [ ] 中文展示名。
- [ ] 阵营。
- [ ] 技能原文。
- [ ] 首夜是否行动。
- [ ] 其他夜是否行动。
- [ ] 需要几个目标。
- [ ] 是否需要选择角色、阵营、善恶、数字或其它输入。
- [ ] 可能产生哪些结果。
- [ ] 是否改变身份。
- [ ] 是否改变阵营。
- [ ] 是否改变生死。
- [ ] 是否造成中毒/醉酒/疯狂/其它标记。
- [ ] 是否影响 setup 人数构成。
- [ ] 是否需要给玩家私密信息。
- [ ] 是否需要公开提示。
- [ ] 是否存在说书人自由裁量。
- [ ] 是否存在高风险交互。
- [ ] 默认玩家信息模板已写好。
- [ ] 规则状态为 `confirmed` 或明确标为 `needs-review`。

## 3. 模板级清单

每套配板模板都必须确认：

- [ ] `templateId` 唯一。
- [ ] `playerCount` 正确。
- [ ] 角色数量等于人数。
- [ ] 阵营人数符合该人数规则。
- [ ] setup 修正已应用。
- [ ] 恶魔伪装不在场，且阵营合理。
- [ ] 没有明显冲突或已写风险提示。
- [ ] 有一句简短玩法建议。
- [ ] 模板风格已标记。

## 4. AI 使用清单

- [ ] AI 配板只从已验证模板里选。
- [ ] AI 提醒不直接改身份。
- [ ] AI 夜晚建议只生成草稿。
- [ ] 每个角色的 `research` 可通过 `roleResearchForAI(scriptId, roleId)` 投影给 AI。
- [ ] 夜晚 AI 请求包含当前唤醒项、当前草稿、已选目标简况、可选结果、`roleKnowledge` 和 `roleResearch`。
- [ ] `knowledgeStatus !== confirmed` 的角色会降低 AI 置信度并提示复核。
- [ ] AI 玩家文案只润色语义，不改事实。
- [ ] AI 复盘不影响未来配板。
- [ ] 真实 AI 不可用时，模板库和手动记录仍可用。

## 5. UI 使用清单

- [ ] 开局列表只显示可玩智能板子。
- [ ] 夜序读取统一 registry。
- [ ] 角色技能读取统一 registry。
- [ ] 玩家状态读取 `GameSession` 投影。
- [ ] AI 配板、夜晚、白天、日记不各自复制角色数据。
- [ ] 二级页面不产生第二套状态源。

## 6. 验收命令

```powershell
npm run lint
npm run test
npm run build
npm run verify:architecture
npm run check
```

如果新增了浏览器流程，还需要补充或运行对应 E2E。
