# 前端架构

## 主线

React + TypeScript + Vite，CSS Variables 提供 Token，CSS Modules/按功能样式隔离。Radix Dialog 只承担 Sheet/Dialog 的焦点与无障碍基础。

当前已实现的是夜间原型；下面目录和统一对局状态是下一阶段的目标架构，不表示白天、配板或常驻面板已落地。

## 目录

```text
src/
  app/                         应用装配、路由/顶层视图切换
  components/ui/               无业务状态的共享组件
  features/game-session/       统一对局合同、时间线与只读投影（计划）
  features/dashboard/          常驻面板、玩家状态板与单座位只读记录投影
  features/setup/              AI配板候选、草稿和确认差异（计划）
  features/script-catalog/     剧本内容、版本化规则知识包与图标目录（后续）
  features/night-workbench/    夜间页面、队列、草稿、确认记录
  features/day-workbench/      白天节奏、提名、投票和日终确认
  features/host-tools/         说书人本机辅助文案与展示工具
  features/ui-lab/             组件展示页
  styles/                      Token 和全局样式
```

`game-session` 是领域合同和投影的边界，不是万能 store。各功能只管理自己的草稿与临时 UI；所有确认后的对局事实只经统一合同追加。

## 状态层次

1. **确认后的对局事实（目标合同）**：已确认配板、座位状态、昼夜记录段、时间线条目、夜序快照、角色变更、投票轮次和日终决议。
2. **功能草稿**：夜间目标/结果、白天提名/举手、配板编辑等。草稿可以刷新恢复，但未确认前不是权威事实。
3. **只读投影**：常驻面板、本局记录、暂列处决、当前角色 Token 都由确认事实生成，不能单独保存第二份摘要或日志。
4. **纯 UI 状态**：预览位置、当前打开的 Sheet、Sheet 内“本局/官方”视图、低亮度和遮蔽开关；按 `sessionId` 隔离的开场白与讨论计时恢复数据也属于本机 UI 状态。

`activeCursorId`、`previewEntryId`、草稿、开放记录段和纯 UI 开关必须分开。唱片、夜序 Sheet 和记录区继续消费同一份夜间队列状态；常驻面板不能通过复制队列或记录自行推导权威状态。

`DiscussionTimerProvider` 是 App 顶层唯一的讨论计时运行时：白天工作台负责开始、暂停、重置和时长设置，首页只读投影当前阶段及剩余时间。它只把恢复副本保存在本机 `localStorage`，不写 `GameSession`、`PhaseSegment` 或 `TimelineEntry`，也不做跨设备同步。`OpeningScriptSheet` 同样按 `sessionId` 保存本机文案，不作为玩家消息或日志。

## 统一时间线与昼夜记录段（计划）

### 记录段

- `PhaseSegment.kind` 为 `night | day`，各自有独立编号和 `open | closed` 状态。
- 每种类型同时最多只有一个开放段；一个开放的夜晚段与一个开放的白天段可以共存。它们不是自动阶段机，也不要求按界面浏览顺序关闭；但新建段的编号不得落后于已存在的另一类段，避免出现“第3夜 / 第1天”的误导组合。
- 打开夜晚/白天工作台、浏览历史、预览角色、切换官方夜序、查询 AI 都不得创建记录段。
- 打开 AI API 设置、测试连接配置、保存模型/Base URL/超时等非敏感配置不得创建记录段；AI 设置页通过 `src/services/settings/` 读写非敏感配置，API KEY 只作为临时输入，不进入前端持久化。
- 某类首次权威保存时：若该类有开放段则复用；否则创建该类的下一编号段。连续保存多个夜间技能必须归入同一夜，连续保存多个白天动作必须归入同一天。
- “结束本夜/结束今天”只关闭当前类型的开放段。关闭后，下一次同类权威保存才创建下一编号；关闭操作不跳转页面、不自动开启另一昼夜。
- 更正、补记和角色变更必须引用原 `segmentId`。它们只追加条目，不能改变原段编号，也不能借“补记”新建当前昼夜。

### 时间线与首页

- `TimelineEntry` 是技能、信息、白天技能、公开事件、提名、票型、处决、状态变更和更正共用的追加式事实。
- 本局记录按 `segmentId` 分组，并保留条目时间与更正链；同一页面允许同时看到同一编号的昼夜段，无需伪造阶段切换。
- `src/features/history/` 只读取统一 `GameSession.timeline`：负责日记筛选、单条详情与追加式更正表单，不保存第二份日志。当前有效投影由 `projectEffectiveTimelineEntries()` 提供；审计视图仍保留原记录与更正链。
- 常驻面板只读投影剧本、已确认配板、座位状态、开放段和最近条目；剧本标题下优先显示所有开放昼夜段，人数/存活统计归入玩家状态板。它没有独立的“首页日志”或“首页状态”写入口。

## 配板与角色变更（计划）

- `SetupCandidate` 仅是 AI/规则层给出的候选；`SetupDraft` 是说书人正在微调的版本；只有 `ConfirmedSetup` 能作为后续夜序与 AI 上下文的基础。
- `ScriptDefinition` 和 `ScriptKnowledgePack` 必须分开保存：前者是导入的角色与顺序内容，后者是来源化的开局修正、冲突、Jinx、伪装策略和复杂度事实。两者以内容哈希绑定；UI 不把只有 JSON 的剧本显示为“可智能配板”。
- 配板检查是 `features/setup/` 的纯函数投影：接收规则包、草稿与说书人选择，输出阻断项、待选择项和人工核对项。它不得读取 UI、写入 `GameSession`，也不得参与夜间技能结算。
- 一次生成 3 套候选。候选生成以合法性、玩家经验适配、双方发挥空间和节奏为首要排序；方案差异是轻量约束，不维护历史配板黑名单。
- 开局前可持续编辑配板草稿，包括换角色和交换座位。候选、草稿、确认配板、线下身份交接必须保持不同命令和状态；当前路线不做常驻玩家端或玩家收件箱。
- 开局后仍可微调，但必须显式确认一个追加式差异事件，并给出从何时起生效。它不能回写历史 `TimelineEntry`，也不能改写当前 `NightRun.queue` 的角色快照；后续创建的工作台才消费新投影。
- 现有 `RoleChangeEvent` 的原则保留：角色变化不直接修改本夜 `queue`。`currentRoleForItem()` 只投影当前显示角色，原队列角色继续作为本夜技能和顺序快照，避免把角色变化误当成自动规则引擎。

## 夜晚工作台

- 官方夜序是版本化只读参考，不进入 `NightWorkbenchState.queue`；切换官方视图不能改变本局光标、预览、草稿或进度。
- `NightRun` 在首次确认后绑定一个 `night` 类型 `PhaseSegment`。结束本夜只关闭该段并返回本局；再次从首页进入夜晚时才显式创建新的独立 `NightRun` 草稿，首次确认才绑定下一夜段。
- 顶部“返回本局”只切换页面：当前存在 `draft` 或更正草稿时，先显示“草稿已保留”的页内确认条；确认返回不关闭夜晚、不推进光标、不写时间线。
- 最后一位结束只显示夜间检查；不会自动进入白天。保存成功后是否移动夜间光标仍是独立于记录段的 UI 决定。

## 白天工作台与投票（计划）

- 白天工作台与夜晚工作台同级，均从常驻面板进入；返回常驻面板不是关闭记录段。
- 白天把 `DayVoteDraft` 与 `DayActionDraft` 分开保存：前者保存提名/举手，后者保存未确认的技能或公开事件表单。顶部“返回本局”会按实际草稿提示票型、技能记录或公开事件已暂存；确认返回后重进白天必须恢复同一草稿。两者都不是 `TimelineEntry`，确认记录前不创建昼夜段。
- 每个 `VoteRound` 记录提名人、被提名人、门槛、逐座位票型、死亡票和完成时间。完成计票只追加本轮记录、清空当前举手草稿，并更新只读的暂列结果。
- `StandingExecution` 是暂列投票结果投影：可表现领先、被覆盖、平票、未达门槛或无候选；它不是玩家死亡状态。
- 只有说书人显式确认“处决 N 号”才追加日终决议与对应 `PlayerState` 的死亡变更；“确认无处决”同样是显式事实。两者都不自动进入夜晚。

## 响应式

- 页面根容器启用 `container-type: inline-size`。
- 响应式布局只改变**信息密度**，不改变对局状态：`<1024px` 为单工作区，`1024px–1279px` 自动显示平板常驻速览（216px），`>=1280px` 自动显示 PC 常驻速览（264px）。
- 常驻速览是统一 `GameSession` 的只读投影，只显示剧本、开放记录段、座位状态和最近确认；不得复制夜序、草稿或昼夜主操作，也不得自行写入时间线。
- 产品页不展示原型导航、布局切换或组件规范入口；工作台内保留明确的`本局`返回操作。开发组件页不进入用户路径。
- 紧凑夜间模式只突出当前角色、技能、目标、结果和主按钮；宽屏增加只读速览，不常驻完整夜序。
- 产品二级界面统一通过全屏 `Sheet` 展开；不在宽屏退化为右侧浮层。`ui-lab` 的浮层仅用于共享组件示例。
- 切换宽度不能重新创建状态、丢失草稿或创建新的昼夜记录段。
