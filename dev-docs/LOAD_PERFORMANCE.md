# 首屏加载测量与按需加载

测量日期：2026-09-08，仅 React 新版。按需加载改进已于 2026-10-16 通过回归并部署，见[部署记录](RELEASE_2026-10-16.md)；下文性能数字仍为原本地测量，并非本次公网重测。

当前已完成第三轮按剧本加载，首屏 JS gzip 总量约 215 kB。前两轮数据保留为历史基线，最新行为和限制见文末。

## 实际变化

App 中配板、身份发送、剧本选择、归档面板，以及昼夜工作台、公聊计时页面改为动态导入；顶部教程也在点击时导入。首页不再请求这些功能的 JS 分包与教程截图。

面板第一次打开前不挂载，首次打开后保留组件实例，即使关闭也不丢失面板内部草稿。工作台仍沿用原有离开即卸载的行为，对局状态继续由同一 GameSession 持有。

原 SetupPanel 内的名单记忆副作用迁入 useGameSession，避免改为按需加载后，首页修改昵称却不记入上一局名单。未改变名单的键名或筛选规则。

每个功能单独使用加载与错误边界。加载中可以返回，失败可以返回或显式重新加载页面。没有自动重载；重新加载仍受原有未保存提醒保护。

## 测量方法

`node scripts/measure-initial-load.mjs .codex-artifacts/load-performance/after.json`

脚本只服务本地 dist，开启 gzip；Chromium 390×900，每次新建上下文、关闭缓存；网络设为 10 Mbps、100 ms 延迟，CPU 降速 4 倍，禁止站外请求，运行三次取中位数。不访问后端或模型。

dashboardObservedMs 是等待 load 事件及首页可见后读取的时间，不能当成精准可交互时间。FCP 是浏览器首次内容绘制时间。以下时间不是实体手机或 VPS 实测，三个样本也不足以证明小幅差异具有统计意义。

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 首屏 JS gzip 正文总量 | 893,567 B | 841,763 B |
| 首屏 JS 解压后总量 | 5,560,118 B | 5,362,654 B |
| 首页可见观测中位数 | 2,513 ms | 2,455 ms |
| FCP 中位数 | 2,404 ms | 2,312 ms |

下载量减少约 5.8%，解压后 JS 减少约 3.6%；时间差较小，不宣称明显提速。初始 CSS 由原单包约 186.32 kB 变为两个初始样式包共约 60.86 kB（构建未压缩体积）。

基线和结果：`.codex-artifacts/load-performance/before.json`、`after.json`。测量时构建入口为 `index-DIYpM98I.js`，实际首屏 JS 文件清单保存在报告中。

## 为什么主包仍大

主入口约 303 kB，但页面仍预加载约 4.97 MB 的 scripts 分包；不能把入口从 5.56 MB 变成 303 kB 当作首屏减少 94%。目前所有剧本共享同步 catalog/registry 接口，开局、角色知识、恢复校验等路径均使用它。

第一轮完成时，下一步候选是按剧本异步加载。第二轮先实施下述构建压缩，在保留同步接口的前提下消除重复文本。按剧本加载仍需另外设计当前局、切换与备份恢复的等待/失败处理。

## 剩余边界

- 未进行实体设备长局、真实 VPS 网络和实时模型评估。
- 按需加载意味着第一次打开某功能需要网络；网络中断时显示加载失败。发布时需整套部署 dist，旧页面请求旧分包失败可经显式重载恢复。
- 完整剧本目录仍同步下载；首屏大包警告与既有 CSS 存量告警仍存在。


## 第二轮：剧本重复文本压缩（2026-09-08）

117 个剧本经常重复包含相同角色能力、风险提示和来源地址。新增 `scripts/build/script-text-plugin.ts`，在前端生产构建时从原始 pack 文件生成共享文本常量；长度至少 24 个字符且至少重复 3 次的数据字符串只输出一次。使用 TypeScript 语法树定位对象属性值和数组元素，不替换属性名、类型、导入路径或普通业务代码。

只共享不可变字符串，不共享角色对象和数组；原始知识文件、角色顺序、来源、版本、哈希及同步 catalog/registry 接口都保留。没有新的资料清单需要人工维护，没有增加依赖，也没有改变 GameSession 或说书人确认边界。开发模式与后端仍直接使用原始资料，前端构建每次重新提取。

完整性测试实际执行转换后的全部模块，再将 117 个注册剧本的完整序列化内容与原始 catalog 比较，覆盖能力、夜序、配板模板、研究资料和来源，而非仅比较数量。另测中文、换行、引号、反斜杠、变量名碰撞和无需转换的模块。


同一测量脚本、同样网络/CPU 条件，第二轮结果保存在 `.codex-artifacts/load-performance/text-pool-after.json`：

| 指标 | 第一轮后 | 第二轮后 |
| --- | ---: | ---: |
| 首屏 JS gzip 正文总量 | 841,763 B | 663,142 B |
| 首屏 JS 解压后总量 | 5,362,654 B | 3,569,473 B |
| 首页可见观测中位数 | 2,455 ms | 1,632 ms |
| FCP 中位数 | 2,312 ms | 1,580 ms |

本轮下载量再减少 21.2%，解压后体积再减少 33.4%；相对两轮之前，下载量累计减少 25.8%。时间来自本机分时采样的三次中位数，仍不能代替真实手机/VPS 测试。构建报告中的完整 scripts 分包从 4.97 MB 减至 3.17 MB；不能用该单包数值代替上表的首屏总量。

验证结果：912 项单元测试通过、3 项 live 模型测试跳过；lint、TypeScript/生产构建、架构检查和 diff 空白检查通过。生产浏览器 12 项通过，覆盖完整对局、7/15 人配板与夜序、缺图标、390/1440px 教程与备份、加载失败返回、备份回退/失败以及跨页面编辑保护，证据位于 `.codex-artifacts/load-performance/text-pool-browser`。

本轮没有实现按当前剧本异步下载，完整目录仍在首屏同步就绪，500 kB 大包警告仍存在。这样暂时保留切换剧本和恢复备份时已有的同步行为；后续按剧本加载需要独立实现等待、失败和缓存边界。真实模型、实体设备长局、VPS 验收和部署仍未执行。


## 第三轮：按剧本加载（2026-09-08）

首页保留默认 Catfishing 资料和共用文本，其余完整剧本按需下载。恢复其他剧本的本地对局时，先加载本局资料再挂载 App 和取得编辑权；失败时不启动对局保存，并提供重新加载、导出原存档入口。正在加载期间若检测到存档变化，会重新准备对应资料。

选择板子时仍须走原来的显式确认。资料加载成功后才继续选择/切换；等待时可返回，取消后即使下载晚到，也只留在知识缓存，不执行切换。重复请求合并为一次下载。已注册但尚未加载的剧本不允许悄悄回退为默认剧本。

备份预览只使用轻量目录核对剧本是否受支持。确认恢复后，先下载该剧本，再通过原有编辑租约保存恢复前备份和新对局；下载失败不会覆盖主存档或回退副本。已加载资料在本页面复用；首次访问其他剧本仍需要网络。

### 数据入口与维护

- `allPacks.ts` 保留原始完整注册顺序，仅供生成器和离线全量验收；不要在浏览器组件导入它。
- `scriptManifest.generated.ts` 提供 117 个剧本的轻量列表，`scriptLoaders.generated.ts` 提供异步入口，`scriptAssets.generated.ts` 提供图标检测投影。三者都从原始 pack 自动生成，不是第二份手工知识库。
- 新增/修改剧本后执行 `npm run generate:script-manifest`。`npm run build` 先校验生成文件，过期即失败，避免发布漏掉新增剧本或图标。
- `smartScriptPacks` / `smartScriptRegistry` 现在仅包含已经加载的知识包。浏览全部剧本用 `scriptManifest`；读取完整资料前 `await loadSmartScriptPack(id)`。全量离线工具可显式 `await loadAllSmartScriptPacks()`。
- 现有同步领域测试在测试准备阶段明确载入全目录；独立 loader 测试和生产浏览器验收不以该准备过程证明加载行为。批量剧本浏览器测试的离线枚举已改用 `allPacks.ts`，避免默默只测默认剧本。
