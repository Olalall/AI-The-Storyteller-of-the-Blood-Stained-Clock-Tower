# 夜间 AI 质量回归

更新：2026-10-16（保留 2026-07-27 的角色草稿回归）

## 目标

夜间 AI 是说书人副驾驶，不是规则引擎。它必须能在复杂角色上给出可采用草稿，同时不自动修改身份、阵营、死亡、毒醉、胜负、昼夜或日志。

## 复杂局面固定题库（2026-10-16）

共享题库：`src/services/ai/nightSettlementQualityCases.test-support.ts`。默认回归和可选真实模型测试都从生产 HTTP adapter 构造请求，使用当前剧本的 `roleResearch`、来源 URL、复核日期和 `knowledgeVersion`，不再另写一份 live 角色规则。

| 题目 | 固定事实 | 真实模型应表现 |
| --- | --- | --- |
| HISTORY-HEALTHY | 赌徒上夜中毒，本夜行动前已确认恢复；本夜猜对 | `correct`；不能把历史中毒当作当前状态 |
| ACTOR-poisoned / ACTOR-drunk | 赌徒自己当前中毒 / 醉酒，猜错 | `no-effect`，提醒当前毒醉 |
| TARGET-IMPAIRED | 赌徒健康，猜错的目标中毒且醉酒 | `wrong` 死亡草稿；不能把目标毒醉套到赌徒身上 |
| PUKKA-MISSING-HISTORY | 只知道普卡当前目标，缺上一名毒目标及历史 | `needs_input`，指出上一名目标 / 历史缺失，不编造死亡 |
| PUKKA-CURRENT-DRUNK | 普卡上夜清醒成功使 4 号中毒，本夜行动时醉酒且尚未恢复 | `no-effect`；不能因上夜有效就宣告 4 号当夜死亡 |
| SNAKECHARMER-SWAP | 健康舞蛇人选中真实恶魔 | `swap`，身份 / 阵营 / 新舞蛇人中毒只做草稿；不能写成醉酒 |
| ROLE-CHANGE | 目标已连续两次确认换角色 | 按最新身份判断 `wrong`，不能拿开局身份比较 |
| MISSING-IDENTITY | 目标已选，实际身份未知 | `needs_input`，具体追问身份 |
| MISSING-ROLE | 洗脑师目标已选，但声称角色未选 | `needs_input`，不采用未就绪结果 |

默认离线检查：上述真实请求字段和 prompt 约束、规则来源、已知事实的本地推断、生产 provider 对编造结果 / 缺项回答的降级、AI 停用后的完整 HTTP 降级链，以及草稿应用前后的状态不变。另分别篡改夜晚 ID、唤醒项 ID、上下文版本、选择版本和知识版本，确认陈旧建议不能进入草稿。

本次修正：夜间请求携带最多 1000 字符的当前角色历史摘要（服务端拒绝错误类型与过长输入）；历史不能覆盖当前状态；本地目标核对复用最新已确认身份；后端 AI 停用 / 缺配置 / 失败时只保留说书人已选且就绪的结果，否则要求手动补齐，不再任取首个结果。

规则依据沿用已复核知识，并核对 [舞蛇人官方 Wiki](https://wiki.bloodontheclocktower.com/Snake_Charmer) 与 [普卡官方 Wiki](https://wiki.bloodontheclocktower.com/Pukka)。旧 live 题里“新舞蛇人醉酒”已移除；正确用词为“中毒”。

## 可选真实模型 smoke

真实模型质量 smoke 不进入默认 `npm run check`。原因：它需要外部 API、网络和可能的费用，不能成为日常开发阻塞项。

运行前必须在本地 shell 或 VPS secret 中设置：

```powershell
$env:BOTC_AI_BASE_URL='https://your-provider.example/v1'
$env:BOTC_AI_MODEL='your-model-name'
$env:BOTC_AI_API_KEY='your-secret'
npm run smoke:ai-night-live
```

当前 live smoke 文件：`server/ai/nightSettlementProvider.live.test.ts`。

当前 live 测试复用上述 10 题。每题检查结果 / 缺项是否符合固定预期、回答中是否明确所需依据与待确认变化；“草稿 / 说书人确认”边界必须保留，原局不能改变。判断文本检查模型的总结、缺项、日记 / 玩家信息 / 状态草稿，不用 provider 自动补入的规则事实代替模型答题。

每题仅输出 JSON 元数据：题目、模型、耗时、状态、推荐结果、缺项数、规则事实数、输入来源数及是否通过，不打印局面、回答或凭据。`missingCount` 是单轮列出的缺项数，不是实际多轮追问次数。来源数只证明提供了经过复核的来源，不证明模型逐条正确引用。

比较新旧模型时，在相同题库、相同知识版本下各运行一次，比较失败题、缺项与耗时；需要人工复查依据是否支持结论、是否漏掉确认条件。现有 provider 不返回 usage，本测试不估算 token 或费用。真实运行会联网并产生供应商费用；本轮开发未执行真实模型测试。

## 新角色加入标准

导入新智能板子或补复杂角色时，至少判断该角色是否涉及：

- 死亡 / 复活；
- 身份变化；
- 阵营变化；
- 中毒 / 醉酒；
- 疯狂；
- 延迟结算；
- 胜负；
- setup 人数修正；
- 登记异常；
- 说书人自由裁量。

只要命中任一项，就需要补一条回归用例，或扩展现有用例。

## 测试原则

- 测“可采用草稿”，不测“自动生效”。
- 缺目标、缺角色、缺目标实际身份或缺关键历史时，允许 `needs_input`。
- 目标、角色和可见状态齐全时，不应只因为 `draft.outcomeId` 为空就追问。
- AI 输出必须包含边界提示：`stateChangeDrafts`、`authorityWarnings`、`ruleFacts` 至少命中一种。
- 默认回归测试不得调用真实模型；真实模型只走可选 smoke。

## 当前边界

- 本地回归只做有限显式核对，不处理完整 BOTC 规则。
- 默认离线测试证明上下文、解析、降级与权限边界，不能证明真实模型会正确推理；10 题也不是完整规则覆盖。
- 当前角色历史摘要可能缺失；请求不含整局历史或完整魔典。HTTP 断网仍回到本地候选，不能把候选当作已核实的延迟结算。
- 真实模型 prompt 已要求优先使用 `roleResearch`、`roleKnowledge`、`statusFacts` 和 `selectedTargets`。
- 新智能板子如果引入高风险角色，必须先补角色知识，再补回归。
