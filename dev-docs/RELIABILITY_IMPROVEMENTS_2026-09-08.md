日期：2026-09-08。基线：97c8b7f，React/TypeScript 新版。本轮本地修改尚未部署。

后续进展：建议第 1 项已于同日完成，当前恢复和多标签页行为以 [新验收文档](SESSION_BACKUP_AND_EDITOR_PROTECTION.md) 为准。下文保留第一轮交付时的范围记录。

## 本轮完成

### 对局保存失败

原来 localStorage 写入抛错会从 React effect 传播并使页面白屏。现在由 useGameSession 捕获失败，保持当前内存对局和用户操作；页面提示重试或导出。每次状态更新仍尝试保存，重试使用当前最新状态。成功后移除错误提示与离页提醒；导出不会被当作本机保存成功。

导出格式为当前 GameSession JSON，供人工恢复使用；本轮未增加文件导入界面。浏览器离页提醒受浏览器自身限制，不能代替备份，也无法保证强制关闭进程时有提醒。

### 并发归档

原来的每次请求独立读出整个 JSON，再写回整个 JSON，两次请求可以都成功却覆盖对方。现在同一个 JsonArchiveRepository 实例串行执行整个读、合并、写入过程，并在队列内部判断重复 ID，保留首次结果。更正继续使用新的命令 ID。

写入失败仍向调用方报错，但不会使队列永久失败。临时文件名使用随机 ID，避免同一毫秒命名碰撞；原子重命名后清理临时文件。

适用于当前单 runtime/单仓库实例。多个进程或多个实例共同写同一文件仍不受此队列保护，未来确有此需求再引入跨进程锁或事务存储。

## 下一步建议，尚未实施

### 1. 补齐可恢复的对局备份

第一步做导入预览：展示文件对应的剧本、人数、阶段、导出时间（如有），校验版本与必要字段。真正替换当前局前先备份当前内容，并要求确认。然后补多标签页保护：同一局在第二个页面打开时提示“另一页面正在编辑”，避免旧页面覆盖新记录。

验收应包含：进行中的夜晚导出后重新导入，已确认记录与待填草稿保持一致；无效文件不得替换当前局；两个标签页交替操作不会静默覆盖。

### 2. 建立少量稳定的真人主持验收

保留单元测试，并让核心浏览器测试随 UI 改动同步更新。先稳定一条从 7 人开局到结束归档的路径，再加 15 人和复杂角色分支。检查重点是实际结果，而不仅是按钮能点：返回前一页后状态是否保留、更正是否追加、重复点击是否重复记账、失败后是否能继续。

现有三个 smoke 已修好，但不代表所有浏览器测试或整场线下使用都已验收。每个版本记录实际测试范围和代码基线。

### 3. 提高 AI 建议的可核对程度

建议面板先显示简短候选结论，然后显示依据、缺失信息、待确认影响；展开后再看完整规则解释。例如涉及普卡延迟效果时，明确上一夜目标是否已提供，信息不够就列出具体缺项，不生成貌似确定的死亡结论。

准备 20–30 个高风险固定案例，按醉酒/中毒、角色或阵营变化、延迟效果、规则例外分组。先运行本地结构与权限回归；真实模型抽查需单独授权费用，保存模型标识、输入、输出和人工评价。评价“建议是否正确、是否乱补信息、是否越过确认边界”，不能只看输出是否是合法 JSON。

### 4. 减少首次打开的等待

本次生产构建主 JS 约 5.54 MB，gzip 约 891 KB，已触发体积警告。这是需要实测的线索，尚不是已测得手机卡顿。

先测首次可操作时间，再考虑按需加载教程、复盘或剧本详情。保留一个权威状态源，避免为了拆包复制业务状态。用同一台设备、同一网络条件对比优化前后，确认实际变快再继续。

### 5. 让文档反映实际能力

AGENTS 的前端原型描述本轮已纠正，开发计划和其他历史报告仍需分辨“历史阶段”与“当前结论”。保留一个简短的当前状态入口，分别说明本地可用、真实模型已验证和 VPS 已验证的范围。

建议执行顺序：恢复与多标签保护 → 一条完整主持验收 → AI 质量案例 → 实测后做按需加载。暂不以增加板子数量或全量重写作为下一阶段目标。
