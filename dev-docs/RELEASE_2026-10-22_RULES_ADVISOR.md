# 两字工具入口与钟楼搭档问答

## 本轮变化

主持阶段显示为黄昏、夜晚、黎明、白天、投票、处决。工具入口统一两字，读屏名称与悬停说明仍保留完整含义；保存和重置保持独立，重置继续单独确认。状态待办补充使用说明：从已确认夜间记录留提醒，随后人工核对生死、毒醉；添加待办不改玩家状态，换角与能力继承仍走各自确认入口。

新“问答”入口打开“钟楼搭档”侧窗，手机以全屏呈现。可以搜索板子、选择一个角色或全板，围绕同一主题追问。选板仅改变问答范围，不切换当前对局。回答分结论、规则依据、推断与建议、还需确认，来源链接只能来自服务器已保存资料。新回答从开头展示，失败保留问题，关闭后继续保留本页对话，刷新后清空。最多发送最近四轮同一板子及角色主题的对话。

人格：冷静、耐心、懂主持的同事。先回答再解释，不扮演全知裁判，不嘲讽玩家，不用恐怖故事台词。区分本板原文、历史版本、自制角色与通用提醒；缺少资料时追问，不凭记忆补成已核实裁定。角色、阵营、借来的能力分别核对。问答没有执行动作和写对局的接口。

## 数据与权限

- 使用已有固定服务器 AI、设备口令、跨站校验、请求大小和频率限制；不新增浏览器 API 配置。真实上游地址和密钥不进入问答请求或公开状态接口。
- 客户端仅提交板子 ID、可选角色 ID、问题和有上限的历史。服务器按 ID 从统一角色库及板包读取原文、夜表、研究和版本。伪造规则、会话或 provider 配置字段被拒绝。
- 默认不读取本局身份、昵称、玩家状态、投票或记录。用户主动写入问题的事实会随问题发送给已配置模型。
- 对话仅在 React 内存，不进入 localStorage、备份、归档或服务器对话库。遮蔽时隐藏问答并停用入口；没有自动切板、夜序推进或状态写入路径。
- 真实模型仍可能判断错误。来源白名单能防编造链接，不能机械证明每句话都被来源支持。它不实时上网，使用的是项目保存的规则口径。

## 规则复核与原始问题

首轮四个真实请求均返回有效结构，但人工复核发现“毒醉与唤醒混淆”和“哲学家后续夜晚获得首夜能力”两处质量问题；不能把结构测试的通过当作规则验收通过。补核 [States](https://wiki.bloodontheclocktower.com/States) 与 [Philosopher](https://wiki.bloodontheclocktower.com/Philosopher) 后，补充通用状态依据和共享哲学家知识及引用。

第二轮四个请求通过加强后的断言，但人工发现调查员解释中夹带无关标记的举例；继续约束只举资料支持且与问题有关的例子，并补充否定断言。原始回答和失败证据保留在私有验收目录，不将私人配置或原始日志上传仓库。

## 使用负担检查

工具文案更短且保留完整提示；问答入口独立，不竞争当前技能的确认动作。默认跟随本局板子，角色按资料列出，不要求手输名称。来源和版本可展开查看，输入和关闭均支持触控及键盘。失败不清空问题，关闭不丢回答，也不会产生一条对局记录。危险重置入口与保存保持间隔。聊天只在主动发送时调用模型。

Ego 在本机隔离空间实际点击验证待办说明、设备验证、哲学家提问、来源展开、关闭重开、追问、搜索并切至僵怖，以及390px手机布局发送。隔离点击采用明确标注的测试回复；真实模型验证单列，不能把二者混算为完整真实对局。初期测试页曾缓存中间构建导致资源失败；固定构建并绕过该测试页缓存后重新点击通过，未清理用户数据。生产部署保留旧哈希资源。

公开源码及安装包均通过真实私密值扫描，不上传原始日志、对局、API 地址、密钥或私人配置。部署完成后的数据、配置与健康检查另行追加。实体手机和全部角色组合不在本轮证明范围。
