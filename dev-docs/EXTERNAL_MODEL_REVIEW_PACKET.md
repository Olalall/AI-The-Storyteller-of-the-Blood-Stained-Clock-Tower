## 0. 给外部大模型的使用说明

请把本文作为主要上下文，并按文末“审查输出格式”给出审查意见。  
不要假设这是线上游戏平台；不要建议复制官方魔典；不要建议自动规则引擎；不要建议真实 AI API、VPS、数据库或官方魔典同步，除非明确标成未来风险评估。

必须重点审查：

1. 线下说书人现场是否更省脑、更少误触、更容易恢复错误。
2. UI 是否一屏一个主任务，按钮是否清楚，是否有重复功能。
3. AI 是否只给候选、草稿和建议，没有直接改权威状态。
4. 是否出现第二套 `GameSession`、第二套夜序、第二套日志、第二套玩家状态。
5. 是否有组件直接读写存储、拼 HTTP、拼 SQL、调用 AI SDK 的趋势。
6. 是否有角色 ID 自动结算技能结果、自动死亡、自动昼夜跳转、自动判胜的风险。
7. 开发计划是否合理，是否会过早进入后端、数据库、真实 AI 或复杂同步。

## 1. 产品定位

产品名：**钟楼说书人副驾驶**。

一句话定位：

> 以官方/实体魔典为主要空间视角，为线下《血染钟楼》说书人提供配板草稿、夜晚顺序、结构化记录、白天投票、状态看板、AI 建议草稿和赛后复盘的本地辅助工具。

它不是：

- 不是第二套官方魔典。
- 不是官方魔典复刻。
- 不是远程线上游戏平台。
- 不是自动规则引擎。
- 不是玩家常驻端或玩家收件箱。
- 不是官方魔典同步器、DOM 注入器、WebSocket 逆向器或半自动点击器。
- 不是真实 AI 自动主持工具。

核心原则：

- **说书人是唯一权威。**
- AI、规则知识、配板算法、OCR、导入都只能产出候选或草稿。
- 任何权威状态变化都必须由说书人显式确认。
- 所有更正都追加记录，不覆盖原记录。
- 即使 AI 不可用，夜序、日志、投票、状态、计时、开场白和手动配板仍要可用。

## 3. 前端 UI 总览

一级工作入口以“常驻面板”为核心。二级页面全屏展开，避免多层浮窗。

### 3.1 常驻面板 Dashboard

目标：说书人开局和对局中默认停留的主面板，负责扫视和入口，不承担所有详细操作。

显示：

- 本局剧本名，例如 `Catfishing / 瓦釜雷鸣`。
- 当前阶段，例如第几夜、第几天、记录中或尚未开始。
- 常用工具入口。
- 进入夜晚、进入白天入口。
- 玩家状态看板。
- 当前配板摘要。
- 最近记录。
- 结束对局和历史复盘入口。

主要按钮：

| 按钮 | 功能 | 是否写日志 | 是否改权威状态 | 备注 |
|---|---|---:|---:|---|
| 开场白 | 打开开场白编辑/展示页 | 否 | 否 | 纯主持辅助 |
| AI配板 | 打开 AI 配板与调整页 | 只有确认调整后才写 | 只有确认后 | 候选不是权威 |
| 发身份 | 打开身份领取页 | 当前主要是本机进度 | 否 | 单人聚焦展示，不下发全局数据 |
| 公聊倒计时 | 打开聚焦计时页或白天计时入口 | 否 | 否 | 不结束今天，不写投票 |
| 切换板子 | 打开板子选择/查看页 | 否 | 否 | 当前只读/原型 |
| 齿轮 AI API 设置 | 打开 AI 非敏感配置页 | 否 | 否 | API KEY 不落盘 |
| 进入夜晚 | 打开夜晚工作台 | 首次确认记录才写 | 否 | 不自动进入白天 |
| 进入白天 | 打开白天工作台 | 首次确认记录才写 | 否 | 不自动进入夜晚 |
| 玩家卡片 | 查看/编辑玩家状态与记录 | 状态确认才写 | 是，需确认 | 生死/毒醉/标记必须确认 |
| 日记 | 查看记录与更正入口 | 更正确认才写 | 视更正内容 | 不直接覆盖旧记录 |
| 结束对局 | 打开保存/复盘/重置页 | 保存时归档 | 重置需确认 | 未保存不能重置 |

审查重点：

- 常驻页是否太像信息墙。
- 入口是否过多，是否需要分组。
- 常驻页是否展示了不常用的信息。
- 玩家状态卡是否能在 3 秒内发现死亡、中毒、醉酒和标记。

### 3.2 开场白页面

目标：给说书人准备和展示开场文案。

按钮：

| 按钮 | 功能 | 边界 |
|---|---|---|
| 编辑文案 | 编辑本机开场白 | 不写日志 |
| 保存文案 | 保存本机文案 | 不进入时间线 |
| 恢复默认 | 恢复默认文案 | 不影响对局 |
| 大字展示 | 全屏展示给玩家看 | 不发送、不计时 |
| 退出展示/关闭 | 返回 | 不写日志 |

审查重点：是否和公聊计时、公告发送混淆。

### 3.3 AI 配板与调整页面

目标：生成或展示配板候选，解释为什么这样配，允许说书人手动调整，最后显式确认。

当前页面分层：

1. AI 配板建议列表：展示多套候选组合。
2. 候选详情：角色组合、适合玩家、主持打法、给信息建议、节奏、风险。
3. 说书人草稿：座位与角色、交换角色、更换角色、修改昵称。
4. 开局人数修正：例如外来者数量调整提示。
5. 恶魔伪装建议：三列，优先未在场角色，可人工改。
6. 确认调整：确认后才影响后续工作台。

关键按钮：

| 按钮 | 功能 | 是否权威 | 备注 |
|---|---|---:|---|
| 查看详情 | 进入候选详情 | 否 | 只读解释 |
| 采用为草稿 | 把候选填入草稿 | 否 | 仍可修改 |
| 交换角色 | 选择两个座位交换 | 否，直到确认 | UI 应避免机械感 |
| 更换角色 | 指定座位换角色 | 否，直到确认 | 需记录差异 |
| 修改昵称 | 改说书人视角昵称 | 是，但非规则状态 | 不作为账号 |
| 确认调整 | 写入配板差异 | 是 | 只能从当前点之后生效 |
| 放弃草稿 | 丢弃当前草稿 | 否 | 不影响已确认配板 |

边界：

- 候选不是确认配板。
- AI 不能自动发身份。
- AI 不能把人数修正、冲突检查、恶魔伪装当成权威规则事实。
- 开局后调整只影响后续工作台，不回写旧夜序快照。

审查重点：

- 候选、草稿、确认配板是否清楚分层。
- 恶魔伪装是否和角色座位在同一语境里，不像另一个模块。
- 配板详情是否帮助说书人“怎么主持”，而不是堆解释。
- 是否可能滑向自动规则引擎。

### 3.4 发身份页面

目标：线下给玩家领取身份时，只展示单个玩家的身份，避免泄露其他玩家身份。

两种模式：

1. 屏幕领取：玩家按号码过来，看平板上的单人身份展示。
2. 实体抽牌：说书人按实体牌流程记录领取进度。

关键按钮：

| 按钮 | 功能 | 边界 |
|---|---|---|
| 选择座位 | 选择当前要展示的玩家 | 不展示其他玩家 |
| 显示身份 | 从遮罩切换为单人身份 | 只显示该玩家投影 |
| 隐藏身份 | 重新遮住身份 | 不写日志 |
| 已领取 | 标记本机领取进度 | 当前不是正式归档事件 |
| 撤销领取 | 取消本机领取状态 | 不改真实身份 |
| 切换实体抽牌 | 仅记录领取进度 | 不替代实体牌 |

审查重点：

- 是否存在“前端拿到全局身份后隐藏”的安全误区。
- 单人展示是否足够聚焦。
- 领取进度是否应进入未来归档事件。

### 3.5 夜晚工作台

目标：按当前板子和在场角色过滤夜序，逐个唤醒，记录选择、结果、告知信息和 AI 建议草稿。

主要区域：

- 页头：第几夜、进度、返回本局、夜间顺序、本局记录。
- 夜间 token 轮播：当前处理角色居中，左右为上一位/下一位预览。
- 当前角色能力说明。
- 本项草稿：目标、角色选择、结果、告知信息。
- AI 技能建议：填入草稿，不直接确认。
- 本项确认区。
- 检查并关闭本夜。

关键按钮：

| 按钮 | 功能 | 是否写日志 | 是否推进 | 备注 |
|---|---|---:|---:|---|
| 返回本局 | 返回常驻页 | 否 | 否 | 草稿保留并提示 |
| 夜间顺序 | 查看本局/官方夜序 | 否 | 否 | 默认本局，可切换完整官方 |
| 本局记录 | 查看本夜记录 | 否 | 否 | 只读为主 |
| 上一位/下一位预览 | 浏览角色 | 否 | 否 | 不能误当推进 |
| 选择目标 | 记录草稿目标 | 否 | 否 | 只在确认后写入 |
| 选择角色 | 记录草稿角色 | 否 | 否 | 角色含义随技能不同 |
| AI推荐 | 根据当前草稿填建议 | 否 | 否 | 标注 AI 草稿 |
| 结果按钮 | 选择本项结算 | 否 | 否 | 可取消/修改 |
| 展示给玩家 | 单人聚焦显示告知信息 | 否 | 否 | 不发送、不确认 |
| 确认本项 | 写入夜间行动记录 | 是 | 否 | 停留当前 |
| 确认并下一位 | 写入并移动到下一夜序项 | 是 | 是，只移动夜序光标 | 不进入白天 |
| 稍后处理 | 保留未完成 | 否 | 可能标记待处理 | 不写权威结果 |
| 检查并关闭 | 关闭当前夜晚记录段 | 是，关闭段 | 返回本局 | 不自动进入白天 |

边界：

- 最后一位完成不会自动进入白天。
- 完成技能不会自动杀人、处决或判胜。
- 赌徒等技能可以给“核对建议”，但死亡状态要说书人另行确认。
- 洗脑师、哲学家等复杂角色只记录选择和建议，不自动跑状态机。

审查重点：

- 结果区和确认区是否重复。
- “本项草稿 / 本项结算 / 确认本项”是否容易理解。
- AI 建议按钮的位置是否恰当。
- 是否存在角色 ID 自动结算趋势。

### 3.6 白天工作台与投票

目标：白天记录技能/公开事件、主持私聊/公聊计时、记录提名和票型、确认处决或无处决。

主要区域：

- 页头：白天工作台、第几天、返回本局、计时器。
- 私聊 → 公聊倒计时。
- 提名：选择提名人和被提名人。
- 举手票型：逐座位记录举手、死亡票、门槛。
- 本日票面：暂列结果、覆盖、平票、未达门槛。
- 日终：确认处决或确认无处决。
- 白天技能/公开事件记录。

关键按钮：

| 按钮 | 功能 | 是否写日志 | 是否改状态 | 备注 |
|---|---|---:|---:|---|
| 开始私聊/暂停/重置 | 控制计时 | 否 | 否 | 不结束今天 |
| 开始公聊 | 私聊结束后开始公聊 | 否 | 否 | 必须手动 |
| 设置时长 | 设置私聊/公聊分钟 | 否 | 否 | 本机状态 |
| 选择提名人 | 草稿 | 否 | 否 | |
| 选择被提名人 | 草稿 | 否 | 否 | |
| 记录本轮票型 | 写入一轮投票 | 是 | 否 | 不杀人 |
| 选择举手座位 | 草稿 | 否 | 否 | 再点可取消 |
| 标记死亡票 | 草稿 | 否 | 否 | 不改生死 |
| 确认处决 N号 | 写处决和死亡状态 | 是 | 是 | 危险确认 |
| 确认无处决 | 写日终记录 | 是 | 否 | |
| 记技能/事件 | 打开白天技能/公开事件 | 确认后写 | 视后续状态确认 | |
| 结束今天 | 关闭白天段 | 是，关闭段 | 否 | 不自动进入夜晚 |

边界：

- “完成本轮计票”不能杀人。
- 暂列处决只是候选结果。
- 只有“确认处决 N号”能改死亡状态。
- 白天结束不自动进入夜晚。

审查重点：

- 票型、暂列、日终处决是否清晰分层。
- 死亡票是否容易误解为改死亡状态。
- 白天技能记录是否包含实际角色、公开声称、目标实际角色和结果。

### 3.7 日记与记录详情

目标：按昼夜、玩家、类型查看结构化时间线，支持更正链。

关键交互：

| 操作 | 功能 | 边界 |
|---|---|---|
| 筛选昼夜 | 看第几夜/第几天/本局/配板 | 昼夜编号不能跳 |
| 筛选玩家 | 查看该玩家相关记录 | 基于结构字段，不靠文本匹配 |
| 筛选类型 | 夜间、白天、投票、状态、配板等 | |
| 双击可更正记录 | 对夜间/白天行动追加更正 | 不覆盖原记录 |
| 状态/投票/处决记录 | 指向对应工作台处理 | 不在日记里直接覆盖 |
| 查看更正链 | 原记录 → 更正原因 → 新记录 | 保留审计 |

审查重点：

- 哪些记录可直接更正，哪些必须回工作台。
- 是否有“为什么不能改”的清晰解释，但不要长文案。
- 日记是否变成后台管理表。

### 3.8 玩家状态面板

目标：常驻页点玩家号码后，快速查看身份、昵称、状态和该玩家相关记录，并追加状态变化。

状态：

- 存活。
- 死亡。
- 中毒。
- 醉酒。
- 自定义标记。

关键按钮：

| 按钮 | 功能 | 是否写日志 | 是否改状态 |
|---|---|---:|---:|
| 标记中毒/取消中毒 | 草稿或确认状态 | 确认后 | 是 |
| 标记醉酒/取消醉酒 | 草稿或确认状态 | 确认后 | 是 |
| 标记死亡/复活 | 草稿或确认状态 | 确认后 | 是 |
| 添加标记 | 添加自定义标记 | 确认后 | 是 |
| 确认状态变化 | 写入 `player_state_changed` | 是 | 是 |
| 查看相关记录 | 过滤该玩家活动 | 否 | 否 |

审查重点：

- 死亡、中毒、醉酒是否视觉区分明确。
- 状态修改是否危险确认足够清楚。
- 状态看板是否只是投影，不保存第二份状态。

### 3.9 结束对局与历史复盘

目标：说书人手动声明胜方，保存本局归档，之后才允许重置游戏；历史复盘可查看任意已保存对局。

结束对局按钮：

| 按钮 | 功能 | 边界 |
|---|---|---|
| 善良获胜/邪恶获胜/暂不声明 | 声明胜方 | 说书人手动，不自动判胜 |
| 保存本局 | 归档当前快照 | 成功后解锁重置 |
| 导出备份 | 导出 JSON | 不含 API KEY |
| 勾选确认重置 | 危险确认 | 未保存不能勾完就重置 |
| 重置游戏 | 关闭当前局并回到新局初始 | 不删除历史归档 |
| 查看复盘 | 切换历史复盘 | |

历史复盘显示：

- 历史归档列表。
- 日期筛选。
- 胜方、玩家数、记录数、死亡数。
- 夜晚、白天、投票、处决、更正统计。
- 当局日志。
- AI 复盘草稿：当局评价、整局复盘、玩家评分草稿、锐评。

边界：

- AI 评分只基于本机日志，不是客观玩家能力评价。
- 不做公开排行榜。
- 不听语音，不知道真实发言质量。

审查重点：

- 保存和重置是否足够分开。
- 复盘评分是否容易误导。
- 历史归档是否应从 localStorage 迁到后端。

### 3.10 AI API 设置页

目标：配置未来 AI 接入的非敏感参数。

字段：

- 调用方式：关闭 / 后端代理 / 兼容接口。
- 接入地址 Base URL。
- 模型名字。
- 临时 API KEY。
- 超时秒数。
- 上下文上限。
- 是否流式返回。

按钮：

| 按钮 | 功能 | 边界 |
|---|---|---|
| 测试连接 | 当前只校验配置完整性 | 不真实调用 AI |
| 保存设置 | 保存非敏感设置 | API KEY 不保存 |
| 恢复默认 | 恢复默认设置 | 不影响对局 |
| 关闭 | 返回常驻页 | |

已经有测试保护：

- `sk-test-not-saved` 这类临时 API KEY 保存后不会进入 localStorage。

审查重点：

- 是否容易让用户误以为已经接入真实 AI。
- API KEY 的安全边界是否足够明显。
- 后续真实接入是否只能走后端环境变量或密钥存储。

## 4. 核心数据与状态边界

当前权威前端合同是单一 `GameSession`。

关键对象：

- `GameSessionState`
- `PlayerSeat`
- `PlayerState`
- `PhaseSegment`
- `TimelineEntry`
- `SetupCandidate`
- `SetupDraft`
- `ConfirmedSetup`
- `NightRunState`
- `VoteRoundEntry`
- `GameArchiveRecord`
- `AISettings`

原则：

- 常驻面板、夜晚、白天、日记、玩家状态都消费同一个 `GameSession` 投影。
- `PlayerState` 当前状态由初始状态 + `player_state_changed` 时间线投影得出。
- 更正通过 `correctionOf` 追加，不覆盖旧记录。
- 夜晚运行态、白天草稿、投票草稿可以是可恢复草稿，但不是时间线事实。
- 配板候选、AI 建议、复盘评分都不是权威状态。

禁止：

- 第二套 `GameSession`。
- 第二套玩家状态。
- 第二套夜序。
- 第二套可写日志。
- 组件里直接拼后端 API、SQL 或 AI SDK。
- 角色 ID 自动结算完整技能结果。

## 5. 当前架构

技术栈：

- React
- TypeScript
- Vite
- Radix Dialog
- Vitest

目录原则：


已完成服务层：

- `src/services/session/`
  - 读取、保存、重置当前 `GameSession`。
  - 原 `game-session/state/persistence.ts` 只保留兼容导出。
  - 未来可替换后端 `loadSession / saveSession / resetSession`。
- `src/services/identity-deal/`
  - 读取/保存本机身份领取进度。
- `src/services/opening-script/`
  - 读取/保存本机开场白文案。
- `src/services/ai/`
  - 生成本地 AI 配板候选。
  - 生成夜晚技能结果建议。
  - 生成赛后复盘草稿。
  - 当前只用 local prototype adapter，不调用真实 AI，不写权威状态。
- `src/services/timer/`
  - 读取、保存白天私聊/公聊倒计时。
  - 迁移旧版本机计时 key。
  - 计时仍是 UI 状态，不写入 `TimelineEntry`。

待拆服务层：

## 7. 防屎山与防架构膨胀规范

### 文件预算

- 入口文件建议不超过 120 行。
- React 页面/业务组件建议不超过 300 行。
- 共享 UI 组件建议不超过 220 行。
- 后端 route 建议不超过 120 行。
- 后端 command handler 建议不超过 180 行。
- 领域纯函数建议不超过 220 行。

超出预算前先拆分，不允许靠继续堆代码推进。

### 代码边界

UI 组件只能：

- 展示状态。
- 收集输入。
- 调用 service 或 dispatch。
- 显示反馈。

UI 组件不能：

- 直接读写 localStorage，除测试和明确本地 provider 例外。
- 直接调用 HTTP、AI SDK、SQL。
- 直接生成复杂归档或 AI prompt。
- 根据角色 ID 自动结算规则。
- 同时维护一份和 `GameSession` 平行的权威状态。

Service 可以：

- 封装 local adapter。
- 封装 HTTP adapter。
- 统一输入输出类型。
- 提供可测试纯函数。

Service 不能：

- 越过说书人确认直接改权威状态。
- 把 AI 结果写入 `TimelineEntry`。
- 保存 API KEY 到前端持久化。

### AI 边界

AI 只能返回：

- 配板候选。
- 规则解释。
- 裁定建议。
- 信息文案草稿。
- 复盘草稿。
- 缺失信息追问。

AI 不能：

- 修改玩家身份。
- 修改生死、毒、醉、标记。
- 执行处决。
- 判定胜负。
- 切换昼夜。
- 发送信息给玩家。
- 写入权威时间线。

### 规则引擎停止线

如果出现以下情况，必须暂停：

- 核心代码开始按角色 ID 自动判定完整技能结果。
- “完成计票”能直接杀人。
- 夜间技能完成后自动进入白天。
- 白天结束后自动进入夜晚。
- AI 建议可一键跳过说书人确认写入状态。
- 自动判胜。

### 状态源停止线

如果出现以下情况，必须暂停：

- 新增第二套玩家状态表。
- 新增第二套夜序。
- 新增第二套配板真相。
- localStorage 中保存多个彼此竞争的权威快照。
- Dashboard、夜晚、白天、日记各自维护摘要而不是投影。
