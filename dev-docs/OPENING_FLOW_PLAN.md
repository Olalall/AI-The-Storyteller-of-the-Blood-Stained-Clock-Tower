# 7-15 人开局流程计划

状态：设计冻结，待实现。  
目标：把自由人数、多板子、昵称/经验复用、AI 配板和身份交接串成一个低风险开局流程。

## 1. 主流程

```text
选择人数
  -> 选择板子
  -> 填昵称/经验
  -> AI 配板
  -> 说书人调整
  -> 确认开局
  -> 可选身份交接
  -> 手动进入首夜
```

原则：

- 不自动进入夜晚。
- 不自动发送身份。
- 不把上一局身份或状态带到新局。
- 说书人可以跳过 AI，直接手动配板。

## 2. 选择人数

支持 7-15 人。

人数影响：

- 可选板子列表。
- 可选模板库。
- 角色构成校验。
- 默认白天私聊/公聊时长建议。

人数不应该导致：

- 页面维护不同状态结构。
- 为 7、8、9、10 人分别写独立页面。
- 角色结算逻辑按人数散落到 UI。

## 3. 选择板子

只展示已经通过智能板子验收的板子。

板子卡片建议显示：

- 名称。
- 适用人数。
- 知识状态。
- 模板数量。
- 最近更新日期。
- 是否有待确认规则。

未完成智能导入的板子不进入开局列表，只能停留在开发/导入流程。

## 4. 昵称和经验

字段：

```ts
interface RosterSeatInput {
  seatId: number
  nickname: string
  experience: 'new' | 'standard' | 'veteran'
}
```

规则：

- 未填写经验时默认为 `standard`。
- 可以导入上一局座位昵称和经验。
- 不导入上一局身份、阵营、状态、日志、票型、胜负、复盘评分。
- 经验只用于提醒，不用于强制分配角色。

## 5. AI 配板

AI 配板页实际做的是：

1. 从当前板子和人数的合规模板库抽取 3 套候选。
2. 展示角色组合、恶魔伪装和简短建议。
3. AI 根据昵称/经验给出提醒，例如“这套对新手信息量偏大”。
4. 说书人手动调整。
5. 通过人数构成和角色冲突校验。

AI 不能直接生成一套未验证板子。

## 6. 说书人调整

允许操作：

- 更换角色。
- 交换两名玩家的角色。
- 修改昵称。
- 调整恶魔伪装。
- 放弃当前候选，换另一套候选。

所有调整都写入开局差异记录。

## 7. 身份交接

确认开局后出现身份交接入口，但不强制进入。

支持三种方式：

1. 单人屏幕领取：平板只显示当前玩家身份，遮住其它信息。
2. 实体抽牌：说书人线下发牌，本工具只记录领取进度。
3. 线下已处理：直接标记某座位身份已交接。

身份交接完成也不会自动进入夜晚。

## 8. 重置后的引导

重置游戏后回到开局第一页：选择人数。

如果有上一局归档，可以显示：

- 复用上一局昵称/经验。
- 从空白座位开始。

这一步不应该显示旧身份或旧状态，避免误导。

## 9. 验收标准

- 能从 7、12、15 人分别创建新局。
- 复用上一局昵称/经验后，身份和状态为空白新局。
- 未填经验的玩家被当作标准玩家。
- 选择板子后只能看到该板子、该人数的合规模板。
- 确认开局前，夜晚和白天入口不会自动推进。
- 身份交接只暴露单个座位身份，不泄露完整局面。
