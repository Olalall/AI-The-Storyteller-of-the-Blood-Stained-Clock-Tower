# iPad 主持准备与返回编辑检查

页面回到前台时立即用现有编辑锁检查权限，不再只等五秒轮询。另一个标签仍在主持、存档已被更新、页面已进入返回缓存或保存失败时，原来的保护继续生效。没有改变存档版本、角色判定、API 私有配置和设备邀请口令。

新增 `playwright.ipad.config.ts` 和 `npm run test:e2e:ipad`，复用 WebKit 与现有真实编辑锁、生产构建和 PWA 测试。目标尺寸为 768×1024、820×1180、1180×820、507×768；分别覆盖常见平板竖屏、横屏和分屏。运行前先执行 `npm run check`，测试期间保持这份构建不变。

新增十五人新局、身份交接遮蔽、转屏保留输入、夜晚草稿、离线记录与投票、导出后在新浏览器环境确认恢复的流程。前台恢复事件单列为合成事件补测，使用真实 Web Locks，延迟轮询后验证立即接手，并确认不能抢占活跃页面。缩短视口只检查布局和滚动触达，不能当作实体 iPad 软件键盘验证。

使用前可在 iPad 的 Safari 打开站点，首次输入站主邀请口令后记住设备三十天，无需填写 API 地址或密钥。选定 Safari 或主屏幕应用后用同一入口主持，不依赖两者自动共享对局或授权。电脑已有局需先导出 JSON，再在 iPad 的“备份”中选择文件、预览并确认恢复；新设备不会自动获得电脑本机对局。

本地验收通过：`npm run check` 为2,998项通过、23项条件跳过，lint、类型、生产构建、PWA和架构检查完成；后端构建与启动 smoke 通过。分批浏览器验收覆盖12项平板主持流程、24项问答检查、32项编辑保护检查，共68项有效通过。IndexedDB故障注入连续三次通过，只计一条覆盖，不重复相加。两项要求真实命中脏数据返回缓存的路径未命中而跳过；合成事件补测不能替代这两项。

补测中保留了原始失败记录。返回导航需先等页面和剧本资料就绪，再检查编辑保护；现分别记录准备时间和保护出现时间，原来的快速刷新总耗时、零写入与存档全文断言保持。故障桩改为拦截`IDBFactory.prototype.open`并核对实际命中次数，避免没有证据确认故障已触发。恢复备份等待真实重载完成，窄屏返回按钮沿用已有短文案匹配。
