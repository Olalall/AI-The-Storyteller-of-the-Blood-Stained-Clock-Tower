# UI HTTP Adapter 决策文档

## 结论

推荐方案：**默认继续使用本地 local adapter；HTTP adapter 作为后续高级/实验选项；不在当前无人推进中改 UI。**

原因：

- 这是线下主持工具，现场稳定性优先。
- 说书人不能因为本地 runtime 没启动、端口被占用或网络异常而无法继续记录。
- 当前 UI 原型已经满意，不能在无人推进中改变默认数据路径。
- HTTP runtime 已通过 smoke，但仍缺少 UI 侧 loading、超时、失败提示和回退体验。

## 三个方案对比

| 方案 | 判断 | 优点 | 风险 |
|---|---|---|---|
| 默认 local，HTTP 作为高级选项 | 推荐 | 离线可用，现场最稳，符合当前原型 | 后端能力需要手动开启后才能使用 |
| 默认 HTTP，本地 fallback | 不推荐当前做 | 更接近未来 VPS/多设备 | runtime 未启动会影响现场；需要错误提示和回退策略 |
| 设置页手动选择 | P1 可做 | 可控，便于测试不同路径 | UI 增加复杂度；需要用户理解“本地/HTTP”区别 |

## 推荐落地顺序

### 当前不做

不切默认 adapter，不增加设置项，不改 UI。

### 下一次需要用户确认后再做

如果你确认进入第 4 阶段，建议做：

1. 在 AI/API 设置或开发设置里增加“归档存储路径”选项。
2. 默认值保持“本机浏览器”。
3. 可选“本地后端 HTTP”。
4. HTTP 失败时明确提示，不静默丢数据。
5. 保留一键回到本地 adapter。

## UI 接入前必须补的体验规则

- 保存归档时必须显示 loading。
- HTTP 失败不能自动重置当前局。
- HTTP 失败必须保留本地草稿。
- 超时要给明确提示，例如“本地后端未启动或端口不可用”。
- 不能把 fake review draft 表达成真实 AI。
- 不能因为 HTTP adapter 接入改变说书人确认流程。

## 验收标准

未来如果进入第 4 阶段，至少要验收：

```powershell
npm run test
npm run test:e2e -- --workers=1
npm run smoke:backend
npm run check
```

浏览器操作必须覆盖：

1. 默认本地 adapter 可以保存归档。
2. 选择 HTTP adapter 后可以保存归档。
3. HTTP runtime 未启动时不丢当前局。
4. 失败后可以回到本地 adapter。
5. 保存成功后才能执行重置。

## 当前状态

第 4 阶段已按推荐方案实现：

- 默认继续使用本机浏览器。
- HTTP adapter 作为高级选项。
- HTTP 失败时保存到本机浏览器备份。
- 不接真实 AI。
- 不部署 VPS。
- 不新增数据库或生产依赖。

后续如果要进入 VPS 部署准备，必须单独确认部署目标。
